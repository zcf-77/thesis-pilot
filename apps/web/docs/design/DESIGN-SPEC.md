## 1. 设计目标

产品原则只有一句话：**AI 主动判断并提供帮助，重要节点介入，学生最终决定。**

设计要做的，是让这句话在每个界面上都**看得见、分得清、改不坏**：

1. **看得见谁说的。** 学生写的、AI 提的、导师说的、系统算的，一眼能分开。
2. **分得清有多确定。** 已成事实、仅是提议、尚不知道、已经过期，不混在一起。
3. **改不坏正式内容。** 任何会改变正式论文或正式计划的动作，都有且只有一个明确的“决定”入口。
4. **不打扰写作。** AI 的出现有台阶，越高的台阶越少出现。
5. **诚实。** 模拟的、未检查的、不能判定的，就照实写，不用一个绿色对勾盖过去。
6. **好看，而且协调。** 好看来自克制与一致：一套语法、一份令牌、一种节奏。

## 2. 设计语法：铅笔 · 墨水 · 印章

这是整套设计的核心，也是四套方案共有的部分。它来自“朱批”的传统：正文用墨，批注另起一色，定稿要落印。

### 2.1 五种材质

| 材质 | 表示 | 视觉构成（线型 + 底 + 形态） | 用在 | 不用在 |
|---|---|---|---|---|
| **墨** Ink | 已成事实 | 实线描边、纸面实底 | 学生写下的正文、确认过的任务、已采纳的修改、导师原话、历史版本 | AI 的任何未采纳产出 |
| **铅笔** Pencil | AI 的提议 | 虚线描边（轻微手绘抖动）、铅笔浅底、理由用手写字体 | 修订候选、计划调整候选、反馈拆解、语义建议、引用候选、“请 AI 起草”按钮 | 已经生效的内容；系统错误 |
| **印章** Seal | 学生的决定 | 印章形态 + 盖章动效 | 采纳、确认完成、标记已处理，以及这些决定的记录 | AI 判断、系统成功提示、导师认可（本轮没有该状态） |
| **留白** Ghost | 未知 | 虚线描边、斜线底纹、空心圆点 | 不能判定、未检查项、来源缺失、未识别内容、已取消 | 表示“没问题” |
| **旧稿** Stale | 已过期 | 去饱和、右上折角、版本号删除线 | 基于旧正文的候选与评审报告、被替换的证据 | 仍然有效的历史版本（那是墨） |

**规则**

- 材质不单靠颜色表达。每种材质至少有“线型”与“形态”两个非颜色特征，灰度打印与色觉差异下仍可区分。
- **铅笔变成墨，只有一条路：学生点击印章色的“决定”按钮，并通过程序校验。** 这条路径上播放“落墨 + 钤印”动效，其他任何地方不播放。
- 勾选“接受这一处”不等于生效：在点击“采纳所选”之前，被勾选的片段仍然是铅笔。
- 候选差异（提议）与历史差异（事实）用两套样式：前者是铅笔色下划线与删除线，后者是绿 / 红底。
- 印章只属于学生。系统完成一件事用“成功”语气的状态胶囊，不盖章。

### 2.2 材质与业务对象

| 业务对象 | 生成 / 进行中 | 待学生决定 | 学生已决定 | 未知 / 无效 | 过期 |
|---|---|---|---|---|---|
| 修订候选（F05） | 铅笔 · 流动虚线 | 铅笔 | 墨 + 印章「已采纳」；已拒绝为留白 | 校验失败：铅笔 + 危险提示 | 旧稿 |
| 计划调整候选（F07） | — | 铅笔条 + 原位置空心虚框 | 墨条 + 印章 | 无可行解：留白 + 解释 | 旧稿 |
| 任务（F07） | 信息语气「进行中」 | 注意语气「待核验」+ 印章色按钮 | 印章「已确认」 | — | 「已确认 · 需复核」 |
| 导师反馈（F09） | — | 拆解项为铅笔 | 印章「已处理」 | 歧义 / 无法定位：留白 | — |
| 要求结论（F12） | — | 语义建议为铅笔 | — | 不能判定 / 来源缺失：留白；矛盾：注意 | — |
| 评审报告（F14） | 信息语气 | —（评审不产生决定） | — | 未检查项、不能评分的维度：留白 | 旧稿「基于旧稿」 |
| 文献（F13） | — | 引用候选为铅笔 | 墨 | 未取得的内容段：留白；无法核实：留白 | — |

### 2.3 三种层级

**空间层级**（投影是层级的读数）

| 层 | 放什么 | 投影令牌 | z |
|---|---|---|---|
| L0 画布 | 背景与纹理 | — | 0 |
| L1 纸面 | 卡片、稿纸、面板 | `shadow-1` | 1 |
| L2 浮起 | 悬停卡片、吸顶栏、拖拽中 | `shadow-2` | 10 |
| L3 浮动 | 菜单、气泡、副驾坞、任务托盘 | `shadow-3` | 30 |
| L4 模态 | 对话框、抽屉 + 遮罩 | `shadow-4` | 50 |
| L5 指令 | 指令面板、轻提示、会话失效覆盖 | `shadow-4` | 70 |

**强调层级**（一个区域只有一个主角）

1. 决定 —— 印章色实心按钮（`variant="seal"`）：采纳、确认完成。
2. 主行动 —— 主行动色实心按钮（`primary`）。
3. 请 AI 提议 —— 铅笔虚线按钮（`pencil`）：只产生候选。
4. 次要 —— 描边 / 浅底（`outline` / `tonal`）。
5. 可忽略 —— 纯文字（`ghost`）。

强调按“字重字号 → 颜色 → 填充 → 投影 → 动效”的顺序递增，不跳级。同一区域出现两个 1 级或两个 2 级按钮视为设计缺陷。

**介入层级**（AI 主动出现的台阶，对应 F08）

| 级 | 形式 | 何时 | 约束 |
|---|---|---|---|
| L0 静默 | 只记录 | 日常输入、自动保存、派生进度计算 | 不产生任何界面变化 |
| L1 角标 | 导航上的圆点或计数 | 有新候选、后台任务完成 | 稿纸之上最多到这一级 |
| L2 收件箱 | 建议卡进入收件箱，不弹出 | 完成重要章节、持续没有可观察进展 | 必须写明触发、依据、不确定性 |
| L3 页内横幅 | 当前页顶部，可延后、可忽略 | 明显延期、阶段完成、硬截止临近 | 只出现在“今日 / 计划”；同类事件去重并冷却 |
| L4 模态 | 必须选择才能继续 | 版本冲突、会话失效、保存失败可能丢稿 | 不用于任何“建议” |

## 3. 四个方案

四套方案共用同一批组件、同一份令牌契约与同一套语法，区别只在令牌取值和一层很薄的签名样式（`signatures.css`）。

| | A 朱墨 | B 荧光笔记 | C 夜航 | D 晨雾 |
|---|---|---|---|---|
| 一句话 | 铅笔提议，朱笔落定 | 把毕设写成一本好看的手帐 | 凌晨两点，航线依然清晰 | 清晨六点半的图书馆 |
| 模式 | 浅色 | 浅色 | 深色 | 浅色 |
| 主行动色 | 墨黑 | 荧光黄 | 青柠 | 晴空蓝 |
| 铅笔（AI） | 石青蓝 | 紫色荧光 | 雷达青 | 朝霞粉 |
| 印章（决定） | 朱砂方印 | 粉色贴纸 | 橙色仪表标 | 蓝黑墨水章 |
| 形状 | 2–12px 圆角、发丝线、无投影 | 6–28px 圆角、1.5px 黑描边、硬投影 | 3–20px 圆角、细线、辉光 | 8–32px 圆角、毛玻璃、柔投影 |
| 展示字体 | 思源宋体 Black | 得意黑 | Chakra Petch + 系统黑体 | Outfit + 系统黑体 |
| 动效性格 | 落墨：干脆、无回弹 | 弹跳：有回弹、物理位移 | 巡航：线性扫描、数字跳表 | 流动：带模糊淡入、柔和弹性 |
| 图标字重 | regular | bold | regular | duotone |
| 适合 | 长时间写作与审阅 | 任务、计划、通知 | 夜间写作、仪表类信息 | 首页、引导、空状态 |
| 留意 | 朱砂与危险色同为红系，危险态必须带图标与文字 | 密集表格需降噪规则 | 长文对比需克制，导出预览切回纸面 | 辨识度相对弱，毛玻璃层数需限制 |

**设计建议**：以 A 朱墨为主。理由：语法出自朱批传统，A 是它的原生语境；密集模块下最安静；朱砂只在“学生作出决定”时出现，层级最清楚。可选加料是 A + C 昼夜成对。最终由你决定。

选定之后的处理：保留一套（或一对）方案的取值，删除其余方案在 `themes.ts` 与 `signatures.css` 中的块，组件不需要改动。

## 4. 色彩

### 4.1 架构

```text
取值（themes.ts） →  语义令牌（--tp-*） →  组件
                    ↘  daisyUI 主题变量   →  表单基元（toggle / checkbox / radio / range）
                    ↘  Tailwind 工具类（@theme inline）
```

- **组件里不允许出现十六进制色值**，只能引用语义令牌或由它映射出的工具类。
- 令牌按“角色”命名，不按“色相”命名：是 `--tp-pencil` 而不是 `--tp-blue`。
- 四套方案必须提供完全相同的令牌键，由 TypeScript 类型与单元测试共同约束。

### 4.2 令牌分组（共 62 个颜色令牌）

| 组 | 令牌 | 说明 |
|---|---|---|
| 表面 | `canvas` `surface` `surface-raised` `surface-sunken` `surface-inverse` `scrim` | 从底到顶；纸面允许半透明（晨雾） |
| 线条 | `line` `line-strong` `outline` | 分隔线 / 结构线 / 组件描边 |
| 文字 | `text` `text-muted` `text-faint` `text-inverse` | 弱文字不承载关键信息 |
| 行动 | `action` `action-hover` `action-content` `accent` `accent-soft` `accent-soft-content` `focus` | 主行动与品牌强调分离 |
| 材质 | `ink` `pencil` `pencil-soft` `pencil-line` `pencil-content` `seal` `seal-content` `seal-soft` `ghost-line` `ghost-fill` `stale` `stale-soft` `highlight` | 设计语法的五种材质 |
| 状态 | `success` `warning` `danger` `info` `neutral` × `` / `-soft` / `-content` | 实色（圆点与填充）、浅底、浅底上的文字 |
| 差异 | `ins-bg` `ins-text` `del-bg` `del-text` | 仅用于历史版本对比 |
| 保护对象 | `protect-number` `protect-citation` `protect-formula` `protect-lock` | 保护下划线颜色 |
| 助手 | `agent-general` `agent-lit` `agent-content` `agent-format` `agent-progress` `agent-review` | 分类色，不表达好坏 |

完整取值见展台「色彩与令牌」页或 `tokens/tokens.css`。

### 4.3 使用规则

- **主行动色**：每个区域最多出现一次实心使用。
- **印章色**：只用于学生的决定及其记录；在 A 方案中它与品牌强调同为朱砂，因此品牌强调也要节制（仅当前导航标记、关键数字）。
- **铅笔色**：只用于 AI 的提议。助手头像用“助手”分类色，不用铅笔色。
- **状态色**：只表达状态语气；实色不直接做文字，文字用对应的 `-content`。
- **荧光**：一页最多一处“荧光笔划过”；另用于搜索命中与定位闪烁。
- **危险色**：只用于被拦截、失败、破坏性操作；拒绝候选不是危险。

### 4.4 对比度契约

每套方案在生成时按 WCAG 2.x 计算 30 组前景 / 背景组合，不达标则脚本以非零退出、单元测试失败。

| 类别 | 最低对比度 |
|---|---|
| 正文 / 任一表面 | 7 : 1 |
| 次要文字、按钮文字、各类 `-content` / `-soft` | 4.5 : 1 |
| 弱文字、焦点环、铅笔线、空心印章、旧稿文字 | 3 : 1 |

当前四套方案 120 组全部通过，实测值见 `docs/design/contrast-report.md`。半透明表面按等效不透明色（`contrastAs`）参与计算。

### 5.3 中文排版约定

- 稿纸正文两端对齐、首行缩进两字、行高 1.95；界面正文左对齐、行高 1.65。
- 中文不使用斜体表示强调；强调用字重或荧光笔。
- 数字参与对齐时启用等宽数字（`tabular-nums`）。
- 眉题的大写变换只影响拉丁字母；中文眉题靠字距与字重区分。
- 手写字体只用于短句批注，不用于正文、按钮与表单。

### 5.4 字体文件与许可

展示、稿纸与手写三种中文字体当前是**展台子集**：`scripts/subset-fonts.py` 扫描源码中实际出现的字符，只保留这些字形，以便展台可以打包成单个 HTML。**正式应用需要改为按 unicode-range 切片的完整 Web 字体**（或回退到系统宋体 / 楷体），否则学生输入的生僻字会落到系统字体。

全部字体均为 SIL OFL 1.1 许可，图标为 MIT 许可，清单与许可全文见 `licenses/`。

## 6. 形状、描边与投影

| 令牌 | A 朱墨 | B 荧光笔记 | C 夜航 | D 晨雾 | 用途 |
|---|---|---|---|---|---|
| `radius-xs` | 2 | 6 | 3 | 8 | 标记、小徽标 |
| `radius-s` | 3 | 10 | 6 | 12 | 按钮、输入 |
| `radius-m` | 5 | 14 | 10 | 18 | 卡片、菜单 |
| `radius-l` | 8 | 20 | 14 | 24 | 面板、对话框 |
| `radius-xl` | 12 | 28 | 20 | 32 | 大容器 |
| `border-w` | 1 | 1.5 | 1 | 1 | 组件描边 |

- 嵌套圆角：内层圆角 = 外层圆角 − 内边距（不小于 `radius-xs`）。
- 投影四档对应 L1–L4；同一层级内不混用不同档位。
- 方案的投影“语言”不同（A 发丝线、B 硬错位、C 辉光、D 柔光），但档位语义一致。

## 7. 间距与栅格

- 4px 网格：2 / 4 / 8 / 12 / 16 / 20 / 24 / 32 / 48 / 64。
- 组件内：元素间 8，行间 12，卡片内边距 16（紧凑）或 20（舒适）。
- 组件间：卡片之间 24，分区之间 32–48，页面级留白 64。
- 外壳尺寸：航线轨 76（图标 + 文字）；航线条高 56；章节目录 200；副驾坞 376（可在 320–480 间调整）；稿纸内容宽度不超过 44em。
- 密度两档：学生空间用“舒适”；配置台用“紧凑”（行高与内边距各降一档，字号不变）。

## 9. 动效

### 9.1 原则

1. 动效是状态的旁白：每段动效都在解释“刚才发生了什么”。
2. 签名动效只给决定：落墨与钤印只在学生作出决定时出现。
3. 进场从容，离场干脆：离场约为进场时长的七成。
4. 一次只有一个主角；列表交错不超过八项。
5. 可以全部关掉，信息一条不少。

### 9.2 令牌

| 时长 | 基准 | 用途 |
|---|---|---|
| `dur-instant` | 90ms | 悬停变色、焦点环 |
| `dur-fast` | 150ms | 按压、开关、复选 |
| `dur-base` | 230ms | 标签滑块、气泡、菜单 |
| `dur-moderate` | 340ms | 抽屉、卡片展开、列表重排 |
| `dur-slow` | 520ms | 页面转场、对话框、主题切换 |
| `dur-deliberate` | 760ms | 签名动效 |

方案用系数整体缩放：朱墨 ×1，荧光笔记 ×1，夜航 ×0.88，晨雾 ×1.2。

| 曲线 | 用途 |
|---|---|
| `ease-standard` | 状态内变化：颜色、尺寸、位置 |
| `ease-enter` | 进入画面（减速） |
| `ease-exit` | 离开画面（加速） |
| `ease-spring` | 滑块、浮层、印章；由脚本求解阻尼弹簧并采样为 CSS `linear()`，不依赖动画库 |

| 性格参数 | 含义 |
|---|---|
| `enter-transform` / `enter-filter` | 进入动画的起点（位移、缩放、模糊、提亮） |
| `press-transform` | 按压形变（缩放或位移） |
| `hover-transform` | 可交互卡片的悬停形变 |
| `seal-rotate` | 印章落定的角度 |

只对 `transform` `opacity` `filter` `clip-path` 与 SVG 描边做动画，不对布局属性做动画（折叠用 grid 行高）。

### 9.3 签名动效

| 名称 | 对应的状态变化 | 做法 |
|---|---|---|
| 落墨 | 候选被采纳 | 一笔实线沿边框描过，底色由铅笔浅底变为纸面，新增文字变为正文色并闪一下荧光 |
| 钤印 | 学生作出决定 | 印章由大到小落下、轻微回弹，外圈扩散一道印泥 |
| 起草 | AI 正在生成 | 虚线边框流动 + 铅笔涂写线 |
| 擦除 | 拒绝 / 取消 | 铅笔线褪为留白色，底色消失；不闪红、不抖动 |
| 褪色 | 过期 | 去饱和，右上角折角出现 |
| 航线推进 | 阶段完成 | 实线向下一个途经点延伸，涟漪移动 |
| 定位闪烁 | 跳转到正文片段 | 目标片段荧光亮起后褪去 |
| 荧光笔 | 页面最要紧的一句 | 荧光从左到右划过，一页最多一次 |

### 9.4 通用编排

Vue `<Transition>` 命名：`tp-page`（舞台切换）、`tp-pop`（菜单气泡）、`tp-swap`（同位替换）、`tp-list`（列表进出与重排）、`tp-modal`、`tp-drawer`、`tp-toast`、`tp-cmd`；工具类 `.tp-enter` `.tp-pop` `.tp-wipe` `.tp-flash` `.tp-shake` `.tp-mark` `.tp-collapse`。主题切换使用 View Transitions 的圆形揭示，不支持时直接切换。

### 9.5 减弱动效

跟随系统 `prefers-reduced-motion`，也可在偏好中手动切换（根元素 `data-motion="reduced"`）：位移、缩放、弹跳替换为不超过 120ms 的淡入淡出；环境动画停止；“进行中”的涟漪、流动虚线与进度条保留；主题切换不做揭示。

## 11. 状态设计

每个界面在设计时必须回答下面九个问题，答不上来视为未完成：

| 状态 | 必须说明 | 形式 |
|---|---|---|
| 空 | 这里将出现什么；第一步是什么 | TpState `empty` + 一个主行动 |
| 加载 | 保留版面骨架，不跳动 | 骨架屏；AI 起草用涂写，系统忙用转圈 |
| 成功 | 改变了什么（哪个版本到哪个版本） | 就地变化 + 轻提示（可撤销时带撤销） |
| 部分完成 | 哪些完成、哪些没有 | 逐项列出；汇总行写“几项完成、几项失败” |
| 失败 | 原数据是否安全；怎么继续 | 危险语气 + 重试 / 替代路径；不自动消失 |
| 取消 | 已取消；迟到的结果如何处理 | 留白语气 + “迟到结果已丢弃”的记录 |
| 过期 | 基于哪个版本、当前是哪个版本 | 旧稿材质 + 重新生成 / 重新审阅 |
| 冲突 | 冲突的双方是什么；谁来决定 | L4 模态或注意语气，给出明确选项 |
| 未知 | 为什么判断不了 | 留白材质，不给默认值、不给 0 分 |

**诚实标注**：模拟评分、样例文献、模拟连通性等在对象上标一次“模拟 / 样例”，不在每个操作上重复提示；DOCX / PDF 等未接入的能力展示为失败或不支持状态，并给出已实现格式作为替代。

## 12. 文案与语气

- **说人话**：“正文已经更新，这条候选不能直接覆盖新稿”，而不是“版本冲突（409）”。
- **AI 不替学生下结论**：用“我准备了一份调整方案，你看看要不要用”，不用“已为你优化计划”。
- **不确定就说不确定**：“过去 4 天没有观察到正文编辑，但这不代表你没在做实验或查资料。”
- **错误信息三段式**：发生了什么 → 你的内容是否安全 → 接下来可以怎么做。
- **按钮写动作与对象**：“采纳所选（2）”“基于 v13 重新生成”，不写“确定”“提交”。
- **固定术语**：候选（不叫“建议稿”）、采纳（不叫“应用”）、确认完成（不叫“打卡”）、已处理（不叫“已解决”）、参考分（不叫“得分”）、取得范围（不叫“覆盖率”）。
- **不出现的词**：智能、一键、赋能、完美、搞定。

## 13. 无障碍

- 所有可交互元素可用键盘到达；焦点环 2px、偏移 2px，使用 `--tp-focus`。
- 仅图标的按钮必须有可访问名称（TpButton 的 `label`）。
- 分段选择与标签页支持方向键；对话框有焦点陷阱，Esc 关闭后焦点回到触发元素。
- 状态不单靠颜色：胶囊永远带文字，材质带线型与形态。
- 轻提示：普通为 `role="status"`，失败为 `role="alert"`；失败不自动消失。
- 对比度见 §4.4；动效见 §9.5。
- 点击目标不小于 28×28（紧凑密度）/ 36×36（舒适密度）。

## 14. 图标

使用 Phosphor Icons（MIT）。字重由方案决定并通过 TpIcon 注入：朱墨 regular、荧光笔记 bold、夜航 regular、晨雾 duotone。尺寸三档：12–14（行内）、16（按钮）、18–20（导航）。图标不单独承载含义，必须配文字或可访问名称。

### 15.3 常见操作

- **调整颜色**：改 `src/design/tokens/themes.ts` → `vp run tokens`。对比度不达标会失败。
- **新增令牌**：在 `schema.ts` 增加键与说明 → 四套方案补取值（类型会报错直到补齐）→ 在 `theme-map.css` 映射工具类（如需要）。
- **选定方案**：在 `themes.ts` 保留选中的方案并设为默认；删除其余方案对象与 `signatures.css` 中对应的 `@scope` 块。
- **正式字体**：移除 `scripts/subset-fonts.py` 与 `src/design/fonts`，改为引入按 unicode-range 切片的完整字体包。

## 18. 假设与边界

- 目标用户是在校本科生，主要在桌面浏览器使用；移动端只保证可读与基本可操作。
- 本稿的四套方案各只做了一种明暗模式；选定后再决定是否补齐另一种。
- 展台中的交互是组件级演示：状态变化真实发生在页面内存里，但没有持久化、没有服务层、没有业务校验。
- 编辑器样张里的保护下划线是视觉示意（按正则识别数字与引用标记），不代表保护逻辑已实现。
- 星级评价（适配度、辨识度等）是设计判断，不是测量结果。
- 没有做用户测试；“适合大学生”是设计假设，需要真实用户验证。
