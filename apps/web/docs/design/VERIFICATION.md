## 3. 自动化测试覆盖了什么

**单元测试（Vitest，`tests/unit»）**

- 四套方案的令牌键完全一致、无空值、颜色可解析。
- 半透明令牌都声明了用于对比度计算的等效不透明色。
- 对比度计算器与已知参考值一致；四套方案 × 30 组前景 / 背景全部达标。
- 印章、主行动、铅笔三者在每套方案里互不相同。
- 时长阶梯严格递增；弹簧曲线从 0 到 1、时长在范围内；荧光笔记有明显过冲、朱墨几乎没有。
- 状态词汇表：每个状态有文案、合法语气与含义；七种候选状态齐全；印章语气只用于学生的决定；铅笔语气只用于 AI 的提议；未知类结论用留白语气。

**端到端测试（Playwright，`tests/e2e»）**

- 九个展台页面加载且没有运行时错误。
- 方案切换并在刷新后保持；同一页内嵌套的四套方案互不串味（主按钮底色与投影各用各的）。
- 减弱动效后时长令牌被压缩。
- 候选：采纳前是铅笔（已勾选的片段也仍是铅笔）→ 采纳后落墨、出现印章、未接受的片段恢复原文 → 撤销回到待审阅；没有任何片段被接受时不能采纳；被拦截与已过期的候选没有采纳入口。
- 任务只能由学生确认；计划调整候选采纳 / 保留原计划；评审报告在正文更新后标为“基于旧稿”。
- 表单校验的错误与修正；对话框的焦点陷阱与 Esc 后焦点返回；分段选择的方向键操作；失败提示不自动消失且带下一步；仅图标的按钮都有可访问名称。
- 编辑器样张（真实 Tiptap 3.33.1）：输入、字数变化、撤销恢复、插入表格、设置标题、数字与引用的保护标记。

这些测试验证的是**组件与设计语法是否按规范工作**，不是业务闭环；业务流程尚未实现。

| # | 问题 | 怎么发现的 | 处理 |
|---|---|---|---|
| 1 | 晨雾主按钮文字对比度 4.4997，低于 4.5 | 令牌生成脚本的对比度检查失败 | 主行动色调深为 #2B66F6，渐变终点同步调整 |

## 6. 未验证 / 已知限制

- **浏览器**：只在 Chromium 158（headless）验证。Firefox、Safari、真实 macOS / Windows 字体渲染均未验证。签名层使用 CSS `@scope»，动效使用 `linear()» 缓动与 View Transitions，稿纸使用 `color-mix()»；这些都需要较新的浏览器版本，旧版本下的降级表现没有测试。
- **字体**：截图环境的中文界面字体是 Noto Sans CJK；在 macOS（苹方）与 Windows（微软雅黑）上的字重与行高观感可能不同。展示 / 稿纸 / 手写字体是子集，展台之外输入的字会落到系统字体（编辑器样张里输入生僻字即可看到）。
- **无障碍**：只做了键盘可达、焦点返回、可访问名称与对比度的自动检查；没有用屏幕阅读器实测。
- **性能**：没有测量。晨雾的毛玻璃与流动光斑在低端设备上的表现未知。
- **动效观感**：自动化只能断言状态与令牌，动效是否“好看”只能在浏览器里实际观看。
- **用户**：没有做用户测试；“适合大学生”是设计假设。
- **业务**：F01—F20 的可操作闭环、Mock 服务、编辑器适配层、备份恢复、导出等均未实现，M01—M20 中除工程复现（M01）的子集外都不适用于本阶段。
- **MuffinOffice**：随需求提供的文档引擎没有运行、没有接入（当前环境没有 Docker 守护进程，需求也明确本轮不接入）。
