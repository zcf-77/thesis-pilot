# ThesisPilot 开发对话与提交证据

仓库文件为 [chat-history.json](../../../docs/evidence/chat-history.json)。入库范围为可确认归属该项目的开发对话、对应设计和文档工作、开发子代理的配置与执行。比赛口径与原件保管见 [证据规范](../../../docs/evidence/README.md) 和 [赛事要求](../../../docs/competition/requirements.md)。

## 从新需求开始记

1. 收到新增需求就登记这段实际用户提示及真实时间。一次聊天的第一条用户消息标记为 `conversation_start`，后续开启一轮的用户消息为 `turn_start`，已开始一轮内的用户补充或纠正为 `interjection`。保留原有顺序、失败、插话和可见 AI 回复。新增需求记录可以先留空提交数组，后续实证补齐。
2. 用户明确要求某条消息、任务或会话不记录时，先排除该范围及其派生条目。沿原件检查改用其他消息 ID 的复述、摘录、任务派发和附件，独立保留未被排除的对话。只在本机 Git 忽略的 `docs/evidence/private/chat-exclusions.json` 保留必要的稳定标识，后续历史补录先读取它。按指令范围使用 `thread_ids`（整聊天及后代）、`turn_ids`（整轮及仅源于该轮的派发）、`item_ids`（具体消息及独立副本）。不在入库文件、提交说明或旁支索引里留下被排除内容或标识。若此前已入库，先核实影响和用户要求，再处理历史。
3. 查平台实际可见记录。首次数据来自本机 Codex rollout 与已投影的可见历史，子代理用真实父子派发关系。其他工具尽量使用原始导出，或按比赛规则采用截图或录屏。明确缺失、失败、取消和中断。不将系统上下文、内部推理、历史摘要或合成输入当用户消息。
4. 对用户授权纳入本项目档案的逐轮对话，逐字保留正文、换行、可见问答和可核验图片附件。完整日志留在本机。对照项目的密钥和论文保管约定，检查明确排除的消息及跨项目内容。执行事件保存可信时间、操作、状态、退出码或可核对结果，保留原始工具载荷的本机定位。如归属、分享范围或是否排除有实质歧义，问用户。

## 多子代理协作

- 协调者按会话、独立智能体或开发线路分配不同的记录范围。子代理并行整理原文、原件定位与提交证据，提交各自的片段或映射给协调者，避免同时改写同一个 JSON。
- 只有协调者合并。操作前重读最新文件，按稳定 ID 追加或补齐自己的字段，审查重复项与其他会话的新改动。提交前核对与原件的差异及排除范围，原子替换文件，防止中断产生半个 JSON。发现同一记录的证据或内容冲突时请对应整理者核实，保留既有证据。
- 新增需求、关键纠错、智能体派发、验证结果和提交形成后更新对应条目。遵循项目已有的提交和施工授权，归档操作不改变授权范围。

## 归档结构和复验

- `development_tracks` 维护开发线路 ID。用 `conversations[].turns[]` 记录可见交流、执行、已核实提交和关联子代理运行。消息分段保留用户正文和附件可用性。使用带时区的原始时间，来源无精确时间时允许空值。
- 优先沿用来源自带的稳定 ID 和序号。只有截图或录屏时，从已存原件及实际位置派生稳定 ID，便于去重并追溯。
- `agents` 独立维护智能体 ID、角色描述、构建或派发提示词和来源。 `agent_runs` 引用智能体 ID，记录父聊天或父代理、派发及后续输入和执行轮次。外部设计智能体拿到真实材料后补录其版本和执行，仓库任务说明作为关联证据。
- 每条源记录用 `source` 说明原件种类、Git 忽略的相对路径与 SHA-256，并保留可核对的原始行号或序号。原件不可得时标注缺失或可恢复范围，不能将局部投影标记为完整原始日志。
- `baseline_commit` 对应会话开始时的工作基线。`commits` 只写实证确认的完整 SHA、关系（如 `created` 或 `later_integration`）及源行或证据文档。核对 Git 对象、原始提交输出或既有明确证据。未提交或无法归属时保持空数组，禁止按时间或标题猜配。
- `prompt_chains` 关联核心能力、AC 和相关会话轮次。人工核对该功能的原始提问、AI 修改建议、用户引导修复、验证结果和提交全程可追踪后，才标记为 `verified`。缺失环节写在 `gap`。
- 核心链用 `evidence` 的 `stage` 与 `description` 排列实际过程，原话引用定位到 `turn` 与 `message_ids`，验证文档和提交使用 `document` 与 `commits`。注明后续整理的提交和自行发现的问题，避免当成用户原始纠错。
- 归档更新后运行 `python -X utf8 scripts/build_evidence_showcase.py`，同步 [开发档案展示页](../../../docs/evidence/showcase.html) 内嵌的数据。以 `--check` 复核展示与归档一致。
- 运行 `python -X utf8 scripts/validate_chat_history.py` 和 `git diff --check`。本机有受控原件时，以 `--verify-local-sources` 复核校验值及排除范围。验收时再审短缺、敏感字段和竞赛完整链。
