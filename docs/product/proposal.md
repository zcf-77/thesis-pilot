# 毕设智途：产品方案

> 状态：2026-11-11 进入论文主工作区交互原型与编辑器小样设计，正式应用尚未实现；19 项产品验收均未执行，本文不代表功能、兼容性或用户效果已经验收。

## 1. 项目定位

暂定题目：《毕设智途：基于 AI 智能体的毕业论文进度追踪与可控辅助修改系统》。英文品牌：**ThesisPilot**；仓库目录名：`thesis-pilot`。

面向正在完成毕业论文的学生，以论文主工作区连接论文正文、学校模板与要求、文献材料、导师反馈和任务进度。AI 提供有依据的候选、检查结果和计划建议，学生保留最终判断与采纳权。产品价值尚待真实使用验证。

流程从开题开始，覆盖中期、论文提交及答辩结束，不含院长审批。首轮围绕单人论文项目，先验证指定模板和编辑链路，再承诺输入输出范围。学校租户、学校权限及三校覆盖暂缓；不把院校覆盖数量作为本轮验收前提。

## 2. 工作区与业务闭环

论文正文占据主要工作区域；任务、要求、文献、导师反馈和 AI 会话按需在侧栏或多面板中打开，保留当前论文位置和操作上下文。常规字段原地编辑，回车保存、Esc 取消；说明按需出现，避免依赖弹窗和重复确认。

1. 创建论文项目，可填写个人规划；没有规划时依据已知截止和产物进度提供适度提醒，不编造效率。导入学校模板、规范及参考资料，自动解析并保存来源和资料版本。
2. 从材料中抽取论文要求，关联原文与适用范围。可判定的硬规则由程序执行；语义规则由 AI 辅助解释，不猜测缺失标准。
3. 导入声明支持的论文，保留原始文件和版本；明确章节、表格、公式、图片等对象的可编辑与支持边界。
4. 在综合模式下由 AI 按任务组织专业智能体，或由学生直接选择专业分工；选区、当前章节和用户选择的资料构成明确上下文。
5. 导师反馈通过粘贴文字录入并保留原文（2026-11-14 用户确认）；AI 建议拆解任务、定位和关联证据，用户可纠正不确定项。
6. AI 生成候选改动，程序检查范围、保护项与基础版本；学生查看差异后接受或拒绝，采纳形成新正文版本。
7. 进度来自任务、具体产物版本和人工确认。学生确认完成后自动更新派生进度与风险；明显延期、持续缺乏可观察进展、章节/阶段完成等事件触发低打扰建议。缺乏编辑记录不等于没有线下进展，正式计划经采纳后才改变。
8. 导出已验证范围内的论文和真实变更说明；评审智能体提供独立报告、问题清单和有依据的参考评分。

资料自动解析保存版本，不等于自动改写正文、采纳规则建议或调整正式计划。本轮不引入上传后人工核对发布流程，也不处理规则更新对既有项目的影响评估。

## 3. 范围与验收映射

### 核心范围

| 模块 | 边界 | 对应验收 |
| --- | --- | --- |
| 项目与版本 | 单人论文项目；持久保存与备份恢复；保留原始文件和历史 | AC-001、AC-012 |
| 论文导入导出 | 只承诺实际验证过的模板和对象范围；不支持对象不静默丢失 | AC-002、AC-011 |
| 证据化进度 | 任务验收条件、交付物版本、待核验与人工确认；旧证据可追溯 | AC-003 |
| 导师反馈 | 原文、任务拆解和章节关联；学生处理不等于导师认可 | AC-004 |
| 受控修订 | 明确选区、目标、保护项；程序检查数字、引用、公式及锁定内容 | AC-005、AC-006 |
| 审阅与版本控制 | 差异、逐项接受/拒绝、撤销；基础版本校验与原子采纳 | AC-007、AC-008 |
| 计划调整 | 依赖和日期硬约束、冲突解释、候选方案；学生采纳后生效 | AC-009 |
| 模型失败处理 | 超时、取消、无效输出、不可达、重复请求可恢复 | AC-010 |
| 模板与资料版本 | 导入解析模板及来源资料，自动保存版本；保留原件和解析结果关联 | AC-013 |
| 论文要求管理 | 要求关联原文、范围与版本；硬性可判定要求程序检查，语义要求 AI 辅助 | AC-014 |
| AI 工作区 | 综合与专业分工、侧栏与多面板；明确上下文和候选作用范围 | AC-015 |
| 主动协助 | 重大事件触发、去重和低打扰展示；用户可关闭，不自动采纳 | AC-016 |
| 四资源库 | 智能体、提示词、API、模型管理页；配置版本与运行绑定，密钥受保护 | AC-017 |
| 论文评审 | 仅评审智能体限定为报告、问题清单、参考评分；不直接改论文或确认通过 | AC-018 |
| 文献辅助 | 真实来源可追溯，区分元数据、摘要和已取得全文；不虚构文献或阅读范围 | AC-019 |

### 暂缓与非目标

学校租户和权限、三校覆盖、导师端、多人协作、多端同步、任意论文格式兼容及规则更新影响评估暂缓。不得留下暗示已实现的空入口。

不做整篇论文代写、虚构实验或文献、伪造导师认可；不提供查重率或 AI 检测规避承诺；不训练自有大模型，不做通用办公套件，不承诺任意 DOCX 无损往返，不默认对公网开放论文数据。

## 4. 五专业智能体与权限

| 智能体 | 职责与输出 | 权限边界 |
| --- | --- | --- |
| 文献 | 来源定位、资料整理、检索与引用建议；标明实际取得的内容范围 | 未取得全文不得声称读过全文；不得编造文献、页码与结论 |
| 内容 | 基于论文与资料分析内容，生成受控修订候选 | 不补造数据，不越界修改，不直接写入正式正文 |
| 格式 | 按模板和论文要求检查格式，提出格式修改候选 | 可判定规则由程序检查；不把未知规则猜成学校标准 |
| 进度 | 依据任务、证据、依赖与日期提出状态及重排建议 | 不自行关闭任务、移动硬截止或替换正式计划 |
| 评审 | 输出问题清单、依据位置和参考评分报告 | 只输出评审结果，不承担正文修改执行，不代表导师或学校认可 |

综合模式用于组织任务和专业分工，不扩大任何智能体权限。其他专业智能体可以按职责产出候选或结构化建议，不受“仅评审报告”的输出限制。外部文档与检索内容是不可信材料，不能改变提示、工具权限和写入范围。

## 5. 程序约束与学生采纳

任务状态记录来源、时间、操作者和证据版本。文件存在、字数或模型判断不能自动转为已确认；学生标记导师意见处理完成，应显示“学生已处理”。汇总进度来源于任务状态，不表述为论文质量分。

修订候选绑定基础版本、选区、目标、保护规则快照和配置版本。结构无效、越界、保护违规、重叠冲突或基础版本过期时，拒绝应用；不能以一次“全部接受”绕过程序检查。部分接受后，对最终组合重新检查，在同一事务中校验并创建新版本和决策记录。取消后的迟到响应不能恢复候选或改写正式数据。

不能解析的对象保持锁定或明确拒绝编辑。没有依据时呈现资料缺口；硬性规则与语义建议分别表达，参考评分说明量表、依据和局限，不冒充官方成绩。

主动协助围绕重大事件，避免每次输入、每条消息都弹出提醒；展示应能定位事件依据，支持忽略或关闭。它只提出建议，不能替学生执行正文修订和正式计划调整。

## 6. 已选技术方向与验证门槛

框架方向已确认，正式应用依赖与产品能力尚未验证；隔离原型的依赖和运行结果另行记录：

- 前端：Vue 3、TypeScript、Tailwind CSS、daisyUI、Pinia、Vue Router；统一由 Vite+ 管理工程、Node 与底层 pnpm，精确版本和迁移验证见[技术选型记录](../engineering/architecture.md)。
- 后端：Python、FastAPI、Pydantic、PostgreSQL、SQLAlchemy、Alembic；LangGraph 负责 AI 编排，Celery 与 Redis 承接异步任务；uv、Ruff、pytest、Playwright 用于依赖管理、检查与测试。
- 编辑器方向：优先开源编辑内核，自行实现 Vue/daisyUI 外壳以贴合工作区风格；具体内核在交互原型与编辑器小样验证后确定。MuffinOffice 退为可选服务端文档转换候选，不等待其浏览器 SDK 推进设计与验证；既有研究事实与待验证边界见 [MuffinOffice 接入研究](../engineering/integrations/muffin-office.md)。

首要门槛是用隔离原型验证论文主工作区布局、AI 面板和审阅采纳交互，再用编辑器小样验证候选内核的许可、文档结构、选区、事务、撤销和保护对象能力。模板导入、无修改导出、局部修改导出及重新打开另设兼容性验证，不把交互原型等同于 DOCX 往返能力。

具体模型、API 接入权限、部署方式和复现包仍待选择与验证。技术选择不代表本机已具备服务、用户已有接口权限或依赖已运行。确定性保护、版本和计划逻辑独立于模型验证；真实模型评估与固定响应测试分开记录。

## 7. 验证与执行顺序

验收场景见 [场景验收](acceptance.md)，阶段与日期见 [执行路线](../engineering/roadmap.md)。当前前端以 [设计规范](../../apps/web/docs/design/DESIGN-SPEC.md) 与 `apps/web` 配套组件为依据；旧原型已退役。设计展台不等于全套 Mock 业务完成。

后续先确认主工作区交互与编辑器小样，再通过编辑链路和保护门槛、进入正式应用最小闭环；依次完成资料/规则版本、专业智能体、任务证据与主动协助、资源配置及可靠性检查。所有新增实现任务先定义对应 AC、范围和可执行验证。

已有内部目标继续保留：至少30组修订保护样例、20条反馈样例、10组计划样例，以及经同意的3—5位目标用户试用；它们均未制作或执行，不是官方强制数量，也不是效果成绩。没有真实试用时，只能报告内部场景验证。

参赛展示使用自制或授权脱敏材料，展示来源、真实差异、用户采纳与失败处理。至少三条完整 AI 编程迭代链应来自真实开发；产品内智能体调用不能替代编程证据。比赛材料、干净环境复现与评审权限单独验收，不承诺获奖。
