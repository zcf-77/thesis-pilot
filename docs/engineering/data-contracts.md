# 数据结构与接口契约规范

适用 ThesisPilot 前后端。日期：2026-11-14。本文建立共同规则与领域边界；“已有类型”“已有接口”“已通过真实业务验收”必须分别记录。本轮可接入范围见[接入需求](frontend-integration-plan.md)，工程执行见[后端规范](backend-development.md)和[前端接入说明](frontend-integration.md)。

## 1. 契约来源与完成状态

| 层次 | 当前依据 | 能证明什么 |
|---|---|---|
| 产品约束 | [产品方案](../product/proposal.md)、[产品 AC](../product/acceptance.md)、[架构](architecture.md) | 已确认的功能、数据保护与业务关系，不等于数据库已实现 |
| 网络契约 | 后端各模块 Pydantic schema 与实际导出的 [OpenAPI](../../apps/api/openapi.json) | 已有项目元数据、正式稿和诊断 Job 的请求、响应、类型与路径 |
| 前端契约产物 | 从同一 OpenAPI 生成的 TypeScript DTO、运行时 schema | 结构一致及变化可检查；类型生成不证明服务可用或业务正确 |
| 本地预览 | `domain/types.ts`、各 `lab/state/*State.ts`、备份验证器 | 已有展示、交互和本地数据保护基础；不能直接作为网络 DTO 或数据库结构 |
| 正式业务模型 | 各模块 `models.py`、迁移、service 与真实服务回归 | 持久化、事务和并发不变量；是否通过以当轮证据为准 |

后端 schema 是已实现 API 的定义来源，OpenAPI 是其可审阅快照；前端不得手写一套同名 DTO 再称其由接口生成。字段语义、来源、状态规则和权限仍需本文及模块契约说明，OpenAPI 不能独自表达这些约束。未进入后端 OpenAPI 的业务模块保持“待契约化”。

## 2. 三层结构

| 结构 | 用途 | 允许的内容 | 禁止的混用 |
|---|---|---|---|
| API DTO | 请求与响应传输 | `snake_case`、明确必填/可空、标识、版本、业务枚举 | Vue ref、组件实例、计时器、回调、整份 Pinia 状态 |
| 领域模型 | 业务规则与持久事实 | 实体关系、不可变版本、状态转换、事务约束 | 依赖颜色、按钮文案、路由坐标决定业务结果 |
| 页面 ViewModel | 展示与交互 | `camelCase`、格式化文本、选中/展开、加载状态、草稿 | 将“已显示”“已关闭表单”当作服务端已保存 |

转换在服务适配层或明确的 mapper 中完成。页面可以保留 `title`，接口使用 `name`，但映射必须显式；不能将 DTO 强制断言成 `PreviewProject`。服务响应只更新该命令确认的字段，不能用名称响应覆盖本地正文、计划或资料。

本地编辑草稿、请求状态和服务端确认快照分别保存。是否允许乐观更新由模块契约声明；本轮远端项目名称和取消操作以服务端确认结果为准。请求失败保留输入，不把本地修改标为远端成功。

## 3. 公共字段规则

| 项目 | 统一约定 |
|---|---|
| 实体 ID | 已实现 API 使用 UUID 字符串；ID 表示身份，不包含状态、日期或业务名称。前端列表 key 使用稳定 ID |
| 标识命名空间 | 本地项目 ID、服务实例标识和服务端项目 UUID 分开；完整关联为“服务实例 + 远端项目 ID”，不能仅凭同一个 UUID 跨服务复用 |
| 项目归属 | 项目内对象必须带可验证的项目关联；服务端检查对象与项目一致，不能信任客户端传入 ID。当前只有共享服务令牌，账户归属/会话模型仍待实现 |
| 临时对象 | 前端草稿可有临时 ID，但不得当作服务器已存在的资源；提交成功后显式绑定服务器 ID，不任意替换已有跨页本地引用 |
| 必填/缺省 | 以 OpenAPI `required` 为准。字段缺失与 `null` 不同；JSON 不发送 `undefined`。PATCH 中缺字段是否代表不修改必须逐字段声明 |
| 空值 | `null` 只用于声明可空的字段，表示已知无值；未知、不适用、未检查须用已声明状态或原因表达，不能统一填空字符串、0 或伪造日期 |
| 字符串 | 项目名称可以按明确规则 trim；导师原话、论文、引文和来源摘录保留原文，分析用副本不能覆盖原件 |
| 数字 | 计数/版本为整数；跨 JSON 边界不得超出前端安全整数范围。精确小数、论文数值、单位与公式按业务表示，不经无声明浮点或字符串转换 |
| 时间戳 | 服务器事件保存带时区时间，API 输出 ISO 8601 UTC；前端仅在展示时本地化。“当前预览”“初始样例”等是展示文案，不能放入正式时间字段 |
| 日历日期 | 截止日等使用明确的 `YYYY-MM-DD` 日期语义，不自动转换成 UTC 午夜。项目时区与学校日历尚未定型时保留待定，不套用开发机器时区 |
| 排序与分页 | 列表必须有上限及稳定排序；本轮使用 `limit/offset` 和 `created_at DESC,id DESC`。分页中的 `total` 是该次查询观察值，不承诺并发写入时跨页快照一致 |
| 原件及来源 | 原始文件、导师文字、资料版本与来源定位保留；派生产物引用具体版本，不只保存可变标题或当前 URL |
| 敏感字段 | 凭据不进入 DTO 的普通读接口、日志、前端产物或项目备份；模型配置仅返回允许披露的引用和状态 |

已有预览数据中存在样例 ID、展示日期及 `Record<string, unknown>`。接入不通过类型断言自动“升级”为正式数据；需要明确转换、校验或保留本地预览身份。无法可靠转换的对象不得静默同步。

## 4. 版本必须区分

| 版本 | 作用 | 更新规则 |
|---|---|---|
| 项目元数据版本 | 当前项目名称等服务端元数据的并发控制 | 请求携带 `expected_version`，数据库条件更新成功后递增；409 后重读并重新决定 |
| 正文内容版本 | 某一篇论文的不可变内容快照 | 已支持正式稿导入、按基础版本保存及只读历史。采纳、撤销和恢复写入待 SG-04 |
| 候选基础版本 | 生成候选时读取的正文/计划版本 | 生成后固定，不能为强行采纳改成当前版本 |
| 计划版本 | 正式任务与排期状态的版本 | 候选调整不变更正式版本；学生采纳后事务保存 |
| 模板/要求/配置版本 | 一次运行实际使用的规则与配置 | 运行绑定确定版本；后续编辑不追改历史运行 |
| 文档 schema / 备份 schema | 数据结构的编码和恢复规则 | 结构变化单独管理，不与正文版本或发布版号混用 |
| Git/发布版本 | 开发成果定位 | 不能替代业务对象版本；不为每个开发任务增加产品版号 |

本机 `PreviewProject.document.version`、正式稿 `DocumentRead.version` 和远端项目 `ProjectRead.version` 分属不同对象。保存正式稿使用它的基础版本，改名使用远端项目元数据版本。正文结构版本独立管理。

## 5. 首轮正式 DTO：项目

定义来源为 [projects/schemas.py](../../apps/api/src/thesis_pilot/modules/projects/schemas.py)。下表同时说明业务不变量；HTTP 结构约束以实际导出的 OpenAPI 为准，数据库约束不能假装已全部表达在 JSON schema 中。

| DTO / 字段 | 类型与约束 | 语义及写入权 |
|---|---|---|
| `ProjectCreate.name` | 必填字符串，trim 后 1—200 字符；拒绝额外输入字段 | 用户确认的新项目名称 |
| `ProjectUpdate.name` | 同上，必填 | 本轮只支持名称更新 |
| `ProjectUpdate.expected_version` | 必填严格整数，至少 1 | 用户编辑时所见的项目元数据版本，不可由服务端猜测 |
| `ProjectRead.id` | UUID | 服务端资源身份 |
| `ProjectRead.name` | 字符串 | 已保存名称，映射为页面 `title` |
| `ProjectRead.version` | 整数，数据库保证至少 1 | 由服务端条件更新递增 |
| `ProjectRead.created_at` / `updated_at` | ISO UTC 时间戳 | 服务端事件时间，显示时格式化 |
| `ProjectPage.items` | `ProjectRead[]` | 当前页资源 |
| `ProjectPage.total/limit/offset` | 整数 | 查询总数、实际页大小、起点；请求 limit 为 1—100，offset 至少 0 |

入口：`POST/GET /api/v1/projects`、`GET/PATCH /api/v1/projects/{id}`。列表为空返回空数组；项目不存在返回 404；旧版本更新返回 `PROJECT_VERSION_CONFLICT`（409）。名称更改不涉及正文版本、阶段确认或任务计划。

项目元数据表单只提交名称与必要的元数据版本。截止日、阶段、个人规划、归档、模块和已有工作保留在本机。正式稿使用独立 documents 接口。新增远端字段须同步 schema、迁移、业务校验、Mock、映射、回归和契约说明。

## 6. 首轮正式 DTO：诊断任务

定义来源为 [jobs/schemas.py](../../apps/api/src/thesis_pilot/modules/jobs/schemas.py)。`Job` 是后台执行，不等于学生计划中的 `Task`。

| DTO / 字段 | 类型与约束 | 语义 |
|---|---|---|
| `JobCreate.project_id` | 必填 UUID | 所属服务端项目；创建时检查存在 |
| `JobCreate.kind` | `diagnostic`，可按 schema 使用默认值 | 本轮只运行无模型、无论文写入的诊断图 |
| 请求头 `Idempotency-Key` | 1—128 字符，允许 ASCII 字母、数字、点、下划线、冒号、连字符 | 创建命令身份；同键同参返回同一任务，同键异参 409 |
| `JobRead.id/project_id` | UUID | 任务身份与所属项目 |
| `JobRead.kind` | `diagnostic` | 不承诺解析、生成、检索、评审或导出已接入 |
| `JobRead.status` | `queued/running/succeeded/failed/cancelled` | 服务端持久状态；不由浏览器计时器决定 |
| `JobRead.attempt` | 整数，数据库保证非负 | 已认领执行次数，非网络请求重试次数 |
| `JobRead.result` | `DiagnosticResult` 或空值 | 成功时包含已校验的任务/项目 ID、固定诊断标记和消息。其他 kind 接入时另定结果 schema |
| `JobRead.error_code` | 可空字符串 | 稳定错误码，无原始异常、连接串或私密论文 |
| `JobRead.created_at/updated_at` | ISO UTC 时间戳 | 数据库记录时间 |
| `JobPage.items/total/limit/offset` | 分页对象 | 按 `project_id` 查询，范围与项目分页一致。支持重复 `status` 查询参数，以匹配任一状态后计算结果与总数 |

现有接口支持创建、按项目分页、读取单个和取消。取消 `queued/running` 后持久化为 `cancelled`，重复取消保持幂等，已成功或失败的任务返回状态冲突。服务端续租与执行期限约束结果写入，`JOB_EXECUTION_TIMEOUT` 和 `JOB_RESULT_INVALID` 分别表示业务期限到达与结果未通过校验。用户重新运行失败或已取消的诊断时创建新任务，原任务终态保留。

页面映射如下，未知状态必须报契约错误，不能用默认“完成”兜底：

| API 状态 | 页面状态/含义 |
|---|---|
| `queued` | 排队中 |
| `running` | 执行中 |
| `succeeded` | 映射为现有展示词汇 `done` / 已完成 |
| `failed` | 失败，显示允许披露的诊断 |
| `cancelled` | 已取消 |
| 无对应 API 值 | 现有预览 `partial` 不得凭空映射；其他业务接入时另定契约 |

当前共享服务令牌下幂等键为全局唯一；接入真实账户后必须设计身份作用域并迁移，不能声称现有机制已完成多用户隔离。

## 正式 DTO：正文

路由以 `/api/v1/projects/{project_id}/documents` 为前缀，路径中的项目、正文和历史版本须与响应身份一致。

| 方法与后缀 | 请求 | 成功响应 |
|---|---|---|
| `POST` 前缀本身 | `DocumentImport`，含 `content` | 201，正式稿 v1 |
| `GET /current` | 路径项目 ID | `DocumentRead`，包含当前正文、版本和时间 |
| `PATCH /{document_id}` | `DocumentSave`，含 `expected_version` 与 `content` | `DocumentRead`，版本匹配时追加新版本 |
| `GET /{document_id}/versions` | `limit` 1–100，`offset` 至少 0 | `DocumentVersionPage`，按版本倒序的摘要，无正文 |
| `GET /{document_id}/versions/{version}` | 正安全整数版本 | `DocumentVersionRead`，固定版本的只读内容 |

`content` 为 `{schema_version: 1, json}`。JSON 经过生产编辑器与后端共同校验，拒绝未知字段、节点、标记与属性。章节 ID 必须已初始化，位置按 UTF-16 计数。最大编辑器节点深度 80，节点总数最多 100000。规范结构及允许对象见[正文结构合同](editor-snapshot-contract.md)。

规范 JSON 正文最多 16 MiB UTF-8，正文写入请求与完整正文响应另有 64 KiB 包装空间。普通 DTO 保持原有传输和结构上限。PostgreSQL 使用 `JSON`，以保留合法的 U+0000 转义。历史内容不可修改，版本条件更新和历史插入同一事务提交，历史来源由服务端记录为 `local_import` 或 `manual_edit`。

仅明确无稿才能导入。项目唯一性防止两个窗口创建两份正式稿。已存在返回 `DOCUMENT_ALREADY_EXISTS`，旧基础版本返回 `DOCUMENT_VERSION_CONFLICT`，均为 409。找不到对应正文或版本时返回各自的 404。超预算返回 413，结构不合法返回 422。断线或超时保留草稿并重新查询，结果未确认前不自动再提交写入。

## 7. 全产品实体与关系登记

下列为已确认业务的语义字段与关系，不是尚未实现模块的最终 JSON/SQL 定义。字段名、索引、细粒度状态和端点须在该模块开工时经场景验证进入 OpenAPI；不先生成空表冒充落地。

| 实体 / 归属 | 必须表达的数据与关联 | 不可越过的规则 | 当前正式契约 |
|---|---|---|---|
| Project / 项目根 | 名称、项目元数据版本；后续阶段、日期、规划关联 | 不能因改名称重建正文/计划 | 名称与版本已定义；其他字段待契约化 |
| Document / 项目 | 文档身份、当前版本、支持范围、模板/要求绑定 | 一份正式当前稿，使用受限 Tiptap JSON | 导入、读取和条件保存已实现，模板/要求绑定待接入 |
| DocumentVersion / 文档 | 不可变内容、结构版本、来源、生成原因、时间 | 保存原件和历史，版本源于所属文档 | 手动保存和导入的版本可读，采纳与恢复写入待 SG-04 |
| PlanVersion / 项目 | 任务集合或版本引用、规划依据、约束、候选关联 | 正式计划仅在采纳后变化；硬截止和依赖由程序校验 | 待契约化 |
| Task / 项目与计划 | 标题、验收、起止日期、依赖 ID、证据、学生确认历史 | `todo/doing/verify/confirmed` 是现有预览词汇；模型不能自动确认完成；最终 API 状态机待明确 | 待契约化 |
| Evidence / 项目对象 | 来源对象 ID、具体版本、片段/定位、关联任务、核验状态 | 来源变更可标陈旧；不能仅存标题当证据身份 | 待契约化 |
| Feedback / 项目 | 导师原话、录入时间、未知/已知反馈时间、拆解片段、学生纠正及任务关联 | 原话不可被拆解结果替代；学生处理不等于导师认可；只粘贴文字 | 待契约化 |
| Source / 项目资料 | 原件标识、版本、摘要、类型、来源、提取范围/诊断 | 不覆盖旧原件；区分题录、摘要和全文；文献核验与取得范围独立 | 待契约化 |
| TemplateVersion / 模板资料 | 来源版本、解析项目、支持范围、格式规则、诊断 | 上传直接解析保存版本，无核对发布流程；不承诺未知对象保真 | 待契约化 |
| RequirementVersion / 要求集 | 来源原句、位置、适用范围、规则类型/参数、置信/冲突状态 | 硬规则由程序检查；修正留版本；不引入规则更新影响流程 | 待契约化 |
| Suggestion / 项目和目标对象 | 基础版本、范围、候选片段/计划变化、依据、保护检查、决定记录 | 无采纳不写正式内容；过期、重叠、越界和取消后结果不可提交 | 待契约化；与通知建议分开建模 |
| ReviewRun / 项目 | 正文/模板/要求/量表/配置版本、评审范围、Job 关联 | 仅评审运行不能调用正式改稿入口 | 待契约化 |
| ReviewReport / 评审运行 | 问题、定位、依据、分项参考分、未检查项、限制 | 缺证据保持未知；参考分不等于导师评分；报告固定输入版本 | 待契约化 |
| AgentVersion / 智能体库 | 职责、允许工具、输入输出 schema、提示词/模型版本引用 | 不上传任意可执行代码；资料内容不能扩大工具权限 | 待契约化 |
| PromptVersion / 提示词库 | 模板、变量、适用任务、不可变版本 | 原文/检索内容是不可信参数，不替换系统权限 | 待契约化 |
| ProviderConfigVersion / AI 接口库 | 协议、地址、超时/限流、密钥引用、状态 | 真实秘密只由服务端读取，普通读 DTO 不回显 | 待契约化 |
| ModelConfigVersion / 模型库 | 模型标识、能力、参数、来源核验时间、接口引用 | 能力/费用不猜测；运行固定配置，不随编辑漂移 | 待契约化 |
| Job / 项目 | 类型、输入身份、执行状态、尝试、产物、错误 | 数据库为事实来源；token、租约、outbox 内部字段不当作客户端授权 | 仅 diagnostic 已定义 |
| Notification / 项目与事件 | 真实触发事实、对象/来源版本、依据、不确定性、已读/延后/忽略、去重键 | 无编辑不直接推断无进展；提醒不自动改计划/正文 | 待契约化 |
| Account / 会话 | 未来用户身份、项目访问范围、会话失效/撤销 | 当前共享令牌不代替用户登录；暂不引入租户/学校/角色体系 | 待设计及验证 |

关系约束：项目内任务、反馈、资料、候选、评审和通知不得串用其他项目；同一来源可被多任务引用，但引用必须固定版本。四库配置可以被多个运行引用，具体项目隔离范围在账户接入时明确；历史运行始终保存所用版本。数据库外键、唯一约束与服务校验共同落实，不依赖前端下拉选项保证一致性。

## 8. 原文、锚点与正式写入

导师原话的空格和换行保留；录入时间与导师给出意见的时间分开，未知时间不补填录入时间。拆解项引用原文位置和具体版本，学生纠正独立保存。已有预览 `handled/verified` 不能未经定义映射为导师认可字段。

选区锚点必须说明所用文档 schema、基础版本、对象 ID、范围单位与边界规则。Tiptap/ProseMirror 位置、JavaScript UTF-16 下标、Python 字符下标和 DOCX 对象位置不能互换；正式协议在复杂样例验证前保持待定。不能将当前 HTML 中的像素/字符串位置直接作为跨端持久锚点。

正式采纳服务必须在一次事务中复验候选基础版本、状态、选区、数字、引用、公式、锁定对象和补丁重叠，然后保存新正文版本与采纳记录。部分采纳需验证组合结果，取消和过期响应不得写入。该事务在 SG-04 接入。

## 9. 错误、取消与重试

API 错误固定为 `{error:{code,message,request_id}}`，前端转换为统一错误对象。页面按稳定 `code/status` 判断，不解析中文消息，不展示无法信任的原始响应 HTML/异常体。客户端网络失败、超时、主动停止查询和响应结构错误须与服务器业务错误区分。

| 情形 | 页面行为 | 数据行为 |
|---|---|---|
| 401 / 认证未配置 | 明确不可访问，保留当前草稿 | 不切到 Mock，不把失败当空数据 |
| 404 | 告知对象不存在，允许刷新列表 | 不用本地旧对象假装服务器仍存在 |
| 409 版本冲突 | 保留编辑输入，重新读取并让用户决定 | 不自动换 expected_version 重发旧编辑 |
| 创建请求超时/断线 | 提示结果尚未确定 | 若契约支持幂等，重试复用同键同参；无幂等的创建不自动重试 |
| 导航/更换项目 | 停止旧查询、忽略迟到响应 | 不等于取消后台 Job，不让旧项目结果写入新项目 |
| 用户取消 Job | 等服务端回应或重新查询最终状态 | 不先本地标取消再假定服务端一致 |
| 无效响应/未知枚举 | 显示契约不匹配并保留已知数据 | 不填默认成功状态，不把异常对象强制断言为 DTO |

项目创建当前没有幂等键，网络结果不确定时应先刷新目录核实，禁止自动重复 POST。诊断任务创建具有幂等键；只有新命令才生成新键，修改项目/任务参数后不能沿用旧键。幂等键不等于 request ID，也不是权限凭据。

## 10. 本地备份与远端关联

`PreviewProject` 的本地 ID、正文、模块和历史保持其原有身份；远端关联通过独立 `remoteBinding` 表达。它只记录服务实例、远端项目 ID 和元数据版本等已声明字段，不携带凭据，不证明用户有访问权限。绑定写入后仍必须通过当前服务重新查询；切换服务实例不可复用另一实例的缓存。

本地工作区刷新恢复可以保留合法关联，以便重新查询；将备份恢复为新项目副本时移除关联并生成新的本地身份，不能让两个副本默认改同一远端资源。导入前完成全部结构/关联校验，再原子替换目标本地状态；失败保留原状态与原始备份。

本地预览的“刷新后取消模拟执行”规则不适用于远端 Job。远端任务在数据库中继续存在，恢复只重建查询和展示。接口 Mock 的存储生命周期须明确；内存 Mock 不承诺刷新持久化，也不能与本地工作区备份混为正式服务器备份。

## 11. 契约演进与每模块开工模板

发布新契约前依次更新 Pydantic、实际 OpenAPI、生成 DTO/schema、适配器、Mock、映射和回归。新增可选字段也需核对旧客户端；新增枚举值会影响穷尽分支，不能当作无风险变更。删除/重命名字段、收窄允许值、改变默认值/状态语义必须给兼容或迁移办法。已经共享的数据库迁移遵循后端规范，不能因改类型顺手重写历史。

每个模块任务至少填写下表，并在实现前评审。未知项有明确验证任务与不支持行为，不能空着交给 AI 猜测。

| 项 | 要填写的内容 |
|---|---|
| 需求与 AC | 用户操作、范围、正常/异常结果、业务约束 |
| 实体与归属 | 唯一 ID、项目/父对象关系、数据事实来源、读写权限 |
| 字段字典 | API 名、含义、类型、单位、必填/可空、默认值、来源、校验、是否敏感 |
| 版本与状态 | 哪种版本、合法转换、操作者、取消/过期/冲突/未知、恢复策略 |
| API | 请求/响应 schema、错误码、分页/排序、幂等、并发前置条件 |
| 映射与本地数据 | DTO→View 映射、草稿/缓存边界、旧预览数据迁移或保留方式 |
| 数据保护 | 原文、来源、锚点、受保护对象、事务与历史保存 |
| 验证与交接 | Mock/HTTP共同合同测试、真实服务场景、生成漂移、实际证据、剩余缺口 |

验收不以 DTO 数量或 TypeScript 编译成功替代业务验证。先形成公共规则，再逐模块将上述领域表变为可运行契约；未经验证的文档结构、账户权限与模型能力不提前冻结为“已实现规范”。
