# main 汇总与提交流程

用途：用户调用 `/main` 或要求整理全部改动、汇入 main、推送及清理分支时执行。对应 REQ-006（开发过程证据）与 REQ-012（真实可复现）；不是应用部署，也不代表产品 AC 已验收。

## 1. 读取与盘点

读取 AGENTS、README、CONTRIBUTING、比赛要求、验收、开发规范及协作台账。执行 `git status --short --untracked-files=all`、`git branch -a -vv`、`git worktree list --porcelain`、`git remote -v`，检查每个工作树的未提交改动与任务归属。存在进行中的 merge/rebase、活动任务或其他会话正在写入时，先协调占用，不覆盖其成果。

fetch 目标远端并枚举全部远端 heads；远端不可达时只可报告本地事实。对每个本地及远端业务分支执行 `git log main..<分支> --oneline` 和 `git rev-list --left-right --count main...<分支>`。不能仅依赖 upstream 的 ahead/behind：没有 upstream 的分支同样需要核实。其他 remote 的业务提交也须登记，禁止误删无关远端。

## 2. 小步提交

- 先登记实际文件清单、目的、依赖、对应 AC/需求及验证办法，再动 Git。每个提交只解决一个可解释目标；配套测试、契约与必要说明随实现提交。
- 新开发完成一轮就提交；积压整理只能按现有成果分类，不修改提交时间，不伪装历史开发过程，不恢复旧版本来制造演进。
- 共享底层优先，功能模块其次，最后入口集成与收尾说明。模块互相依赖时说明依赖提交；未接入前不得声称中间提交已具备完整运行能力。
- 显式 `git add -- <文件...>`；禁用 `git add .`、`git add -A`。逐组执行 `git diff --cached --check`、`git diff --cached --stat`、`git diff --cached`，审阅凭据、私人资料和无关文件后再提交。
- 标题采用 `type(scope): 中文具体变化`；正文简短记录“改动及原因 / 验证与结果 / 限制及证据”，通常 3—5 行。不用“更新代码”代替说明，不为提交数量机械拆文件。
- 不重写已有公开提交，不把真实失败抹成成功。当前提交 SHA 由后续证据索引映射，避免自引用。

## 3. 汇入与验证

在现有 main 检出整合；不得 checkout 切换共享主检出。需要隔离时建立独立 worktree，并明确它的文件所有权。汇入每个分支的独有提交，优先快进；发生分叉时保留真实历史并按项目规定整合，不丢弃无法解释的提交。逐项核对冲突中的双方意图，禁止以 ours/theirs 一键覆盖。

工作区干净后 fetch；存在 `origin/main` 时执行 `git rebase origin/main`。如已 up to date 也记录实际输出；新空远端没有目标分支时明确记为不适用。检查迁移 ID、唯一 head 和错误码与远端是否冲突；尚无相关文件才可记不适用。

运行当前范围的门槛。前端依次执行 check、单测、build、E2E，界面变化另核对实际交互；后端执行锁、静态检查、快测、OpenAPI、迁移及适用的真实服务回归；纯文档执行仓库校验及 diff 检查。环境阻断、失败、跳过分别记录。尚未通过必要检查的代码只能作为明确标注的阶段性成果保存，不宣称稳定发布；不得绕过项目发布门槛。

## 4. 推送与清理

确认用户授权代码推送且保持 Private；只推送 main，不自动部署或改仓库权限。执行 `git push origin main`。若远端变化则重新 fetch、rebase、复验后重试；禁止 force push。推送后查询远端 main SHA，与本地 HEAD 核对；查询仓库可见性，失败直说。

清理必须在推送确认后：重新枚举 heads，逐个用 `git merge-base --is-ancestor <分支> main` 证明已合并。所有需要保留的业务提交都须可从 main 到达，补丁相似不等于提交已经保留。分支无法解释或仍有独有提交时保留并报告，禁止为制造干净状态删除。

已授权清理时，对路径和任务归属核实后的干净多余 worktree 执行 `git worktree remove <绝对路径>`，不用 `--force`；再用 `git branch -d <已合并分支>` 删除本地分支。逐项核实并删除已合并的远端临时分支，保留 main、远端默认分支及用户明确保留的分支；清理前说明范围，不把删除请求泛化为删除其他仓库、stash、标签或私人文件。不执行 `git clean -fdx` 或 `reset --hard`。

最后 fetch/prune，再检查 status、所有分支差集、worktree 清单以及本地 HEAD/远端 main。只有实际结果满足“工作区无待提交改动、HEAD 等于远端 main、无待保留的分支独有提交、无多余工作树”才报告完成。忽略的构建产物无需为 status 干净而删除。

## 5. 权限阻断与交付

Git 元数据只读或网络受限时记录实际错误，禁止更改权限、伪造成功或反复无效重试。允许时可在独立可写副本保存真实分组提交；保留原工作区，不据此宣称原目录已干净。安装 Skill 失败则保留本流程作为内容依据，不宣称 `/main` 已注册或可用。

交付给出提交数量及简短主题、验证结果与未通过项、远端状态、清理清单和剩余阻断。正文不重复所有 diff；完整映射存入当轮证据记录。摘要和整理提交不能代替比赛要求的三条完整开发 Prompt 链。
