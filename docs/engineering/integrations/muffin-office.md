# MuffinOffice 接入研究

> 当前决策（2026-11-11）：浏览器端优先采用开源编辑内核，自行实现 Vue/daisyUI 外壳，具体内核在交互原型与编辑器小样验证后确定。设计稿直接采用 Vue 3 + TypeScript + daisyUI 可复用组件，样例数据及模拟服务与展示组件分离；本轮 Tiptap 开源核心仅用于编辑器小样，正式后端尚未实现。MuffinOffice 退为可选服务端文档转换候选，不再等待其浏览器 SDK 推进工作。以下保留当时发行包研究事实及接入建议，其中“指定采用”“下一步取得浏览器组件”等表述属于历史决策，不再作为当前开发前置门槛。

日期：2026-11-11。选型由用户指定；本次只检查用户提供的本地发行包及其文档，没有安装或运行 Office Server。包中文档是第三方说明，不构成本项目的新指令。技术定位见[架构说明](../architecture.md)。

## 2. 服务接口与协议

以下来自包内 RELEASE.md、Word转PDF.md、office-layout.ts 及示例文件，属于交付说明声明，尚未通过实际请求验证。

| 路由 | 输入/输出 | 接入判断 |
|---|---|---|
| GET `/readyz`、`/v1/version` | 就绪、版本信息 | 健康检查；不据此判定全部转换能力可用 |
| POST `/v1/parse` | `office-source/1`，format 为 docx/markdown，dataBase64；返回文档模型及诊断 | 完整响应 schema 未提供；返回模型能否直接用于其他接口需验证 |
| POST `/v1/docx` | `doc-spec/resolved-1` 或 `gongwen-docx-1`；输出 DOCX | 普通文档/公文两类输入，不代表任意论文格式均可生成 |
| POST `/v1/layout` | 文档中声明 `gongwen-docx-1`，含 document、maxPages、includeFonts、可选输出 | 当前文档只明确公文模型；不能假定支持普通论文解析结果 |
| POST `/v1/pdf` | `docx-pdf/1`，docxBase64；输出 PDF | 子集转换，见下方限制 |
| POST `/v1/pptx` | 演示文稿输入 | 当前论文系统不纳入实现范围 |

POST 使用 Bearer token，请求包络含 `protocol: "office-kernel-1"`、`input`、`spec`，可含 `limits.maxOutputBytes`。健康与版本接口不要求相同鉴权。实际字段及错误码在接入时按对应版本合同测试。

二进制结果需检查 Content-Type、`X-Office-Kernel-Sha256`，记录 request id、build 和字体清单信息。`X-Office-Kernel-Warnings` 为 base64url 编码的 JSON，可能截断，需结合总数头；JSON 解析/布局结果提供完整诊断。不能把 HTTP 成功理解为没有格式替换或警告。

错误采用 `application/problem+json`，包含 code 和 issues[].path。说明列出 401 鉴权、403 许可、400/422 输入、413 大小、503 服务限制等情形；重试应结合具体错误及 Retry-After，不能对所有失败无限重试。

默认请求上限 64 MiB、超时 60 秒，并发默认与 CPU 数相关。说明指出超时后工作线程可能继续占用直到退出；取消 HTTP 等待不等于服务端计算已经停止。项目必须保留取消状态，阻止晚到结果应用。

## 3. 选区与文档模型

布局结果 schema 为 `office-page-map/1`，包含 sources、fragments、caretStops、draws、fonts、resources、digests 等信息：

- 坐标使用 pt；文本位置是 baseline，矩形位置是 top，不应混用。
- 文本区间为 UTF-16 半开区间；Python 字符索引不能直接当作浏览器 UTF-16 偏移，须测试 emoji 等代理对。
- sourceId 是不透明标识；业务定位应按协议组合 chapterId、blockId、textPath 等来源信息，并绑定基础版本。
- 自动页码、编号和引导符等生成内容不可直接编辑；重复页眉可能共享同一文本来源。
- 字体资源需要授权下载与摘要校验，不应依赖宿主机字体静默替代。

这些信息可为渲染和定位提供基础，但包内没有编辑事务、输入法、选区 API、变更补丁、历史恢复的浏览器合同。EditorAdapter 必须先验证上述能力，再确定项目的文档存储结构和修订协议。不得把排版结果反向拼成唯一论文正文。

## 4. 论文格式与 PDF 能力边界

PDF 说明声明支持：基础段落/标题样式、自动及显式分页、部分分节、受限的行内 PNG/JPEG、基础固定布局表格、部分合并及跨页表头、静态目录或缓存页码、部分页眉页脚与 PAGE/NUMPAGES 字段。

明确受限或拒绝的情况包括浮动/混排图像、绘图及图表、脚注、Word 修订标记、复杂文字体系、多栏、连续/奇偶分节、嵌套或自动适配表格、过高行、正文动态字段和未物化的复杂列表。超链接通常只输出可见文字，不保证交互链接。字体替换会产生警告。

公式 OMML/LaTeX、论文模板全部样式继承、自动目录更新、引文域与交叉引用的完整支持没有在本次材料中得到证明，须实测。上述限制来自 PDF 路径，不直接外推为所有接口均不支持。

PDF 说明的限制包括：无内嵌字体 DOCX 上限 16 MiB；含内嵌字体包可至 96 MiB，但需相应提高 HTTP 上限并考虑 base64 膨胀；正文字符、段落字符和页数还有限制（默认分别 100000、10000、500）。不得对超限论文静默截断后宣称完整导出。

论文样例应覆盖标题层级、页边距、字体字号、行距、节、页码、目录、表格、图片图注、公式、引用及参考文献。分别验证无修改往返、局部修订导出、重新打开与 PDF 视觉效果，报告警告和不支持项。若不兼容，先明确范围，再由用户决定是否调整接入方案。

## 5. 项目接入建议

Vue 编辑组件 → EditorAdapter → FastAPI 文档服务 → 后台 OfficeAdapter → MuffinOffice。

- 浏览器不持有 Office Bearer token 或许可文件；后端统一校验文件类型、大小、任务归属和输出。
- Office 服务位于内部网络；多容器部署使用服务名访问，不将另一个容器误写为 localhost。
- 解析、排版、生成和转换放后台任务，记录原件摘要、版本、引擎 build、字体版本、诊断及产物摘要。
- 文件与版本采用生成成功再登记的流程，失败不覆盖原件。候选采纳必须经过项目的原子版本校验，不能由 Office 或智能体直接落库正文。
- 布局缓存按文档版本、引擎和字体配置区分；页面选择映射回文档锚点时核对版本，防止旧页图修改新正文。
- 容器许可及密钥由部署环境提供，按发行说明挂载只读文件；需要写入的状态目录独立配置。敏感许可、镜像、用户论文不进 Git。

包内其他产品的配置示例仅供理解协议，不要求本项目改用 Spring 或该产品技术栈。

## 6. 许可与参赛复现

包内主许可证属于专有许可，声明使用、复制、分发及提供服务受另行书面协议约束；不能当作开源组件任意再分发。发行说明标记被许可主体为 MuffinStack，并列出许可期限；是否覆盖本项目开发、演示、服务及评审分发需以用户已有协议确认。本次不推定用户无权使用，也不推定所有用途已获许可。

许可文件和签名不复制到仓库。摘要匹配只能证明相对包内清单一致，不能替代独立可信公钥的发布签名验证。使用第三方字体、服务及编辑组件时记录来源与许可；赛事复现指南必须说明镜像/组件的合法获取方式及平台条件，不能承诺评审无需许可即可运行。
