日期：2026-11-14。用户要求：按照已确认方案搭建后端底层，形成完善开发规范，参考前沿代码仓库的开发模式。此文在实现前建立；实际结果另见本轮证据，不将工程验收计为产品 19 项 AC 完成。

## 范围与决策

新增 `apps/api`，使用 Python 3.13、uv、FastAPI、Pydantic、同步 SQLAlchemy 2、PostgreSQL/psycopg、Alembic、Celery/Redis、LangGraph。API 的数据库路由使用同步函数，由 FastAPI 调度；每个请求/后台执行独享 Session。选择同步事务简化当前单体及 Celery 集成，禁止在 async 路由中直接执行阻塞数据库调用。

首轮仅交付基础设施及项目元数据、诊断任务两条真实切片。诊断任务不调用模型、不处理论文；正式论文结构、受控采纳、四库、文件转换、登录账户与前端联调继续列为待实现。配置一个服务端 Bearer 令牌保护业务 API，缺少令牌拒绝请求；这只是本地/受控联调边界，不冒充用户登录和资源归属授权。

不覆盖现有未提交前端及设计稿。共享文档只增补相关状态；不切换主检出、不部署、不推送。新增代码独立限定文件所有权，测试与代码审查后交付。

## 参考原则

参考 FastAPI 官方 full-stack 模板的配置、测试、迁移、依赖锁和契约生成；保留本项目 Vue 与 SQLAlchemy，不导入模板整套业务。参考 LangGraph 官方的显式图状态及人工决定边界、Celery 的幂等消费与确认语义、SQLAlchemy 的 Session 事务生命周期、uv 的锁定安装。来源、采纳与舍弃逐项记录于开发规范；不以框架流行度替代本项目需求。
