# 后端开发规范

适用：`apps/api`。日期：2026-11-14。本文规定后续开发必须遵守的边界，不代表对应产品功能均已实现。本轮范围见[底座需求](backend-foundation-plan.md)，实际运行结果以会话证据为准；启动命令与配置以 `apps/api/README.md` 为准。

采用**模块化单体、按功能纵切片、小步验证**。一个功能同时交付契约、业务规则、持久化、回归和证据；保持一个数据库事实来源。框架和工具的参考来源及取舍见[参考记录](backend-references.md)。

## 1. 必须执行与按需引入

| 必须执行 | 可选，出现实际需求后引入 |
|---|---|
| 需求与 AC、范围和验收先行；核心异常有回归 | 为跨模块重大决策单建 ADR；一般取舍写任务记录即可 |
| uv 锁定依赖，Ruff 格式/检查，mypy，pytest | pre-commit 本地加速；不能替代 CI |
| 类型化 API、显式事务、并发版本检查、稳定错误码 | 复杂查询复用出现后再提取 repository；不强制空泛 CRUD 基类 |
| Alembic 迁移、迁移审阅、单一 head、真实 PostgreSQL 验证 | 游标分页、读模型、查询缓存按规模引入 |
| outbox、幂等消费、取消与迟到结果保护 | 多调度器、跨服务事件总线、复杂任务编排按实测引入 |
| 文件所有权、真实 Git 提交、证据与交接 | 独立会话多机器才使用协调分支；不强制 main 登记 |

不为五个专业智能体拆五个服务；不为每个业务类建立接口/实现双层；不以测试数量、覆盖率数字或工具数量代替需求验收。

## 2. 目录与依赖方向

| 位置 | 职责 | 边界 |
|---|---|---|
| `src/thesis_pilot/main.py` | 应用工厂、生命周期、统一挂载 | 不承载业务规则；导入模块不连接网络、不建表 |
| `core/` | 设置、错误、鉴权、日志等共性能力 | 不反向依赖具体功能模块；配置不保存业务状态 |
| `api/` | 公共请求依赖、健康检查 | 只处理 HTTP 边界；长任务不留在请求内 |
| `db/` | Base、Engine、Session 工厂 | 不持有全局 Session，不决定业务何时提交 |
| `modules/<feature>/` | 一个业务功能的 router、schemas、service、models | 跨模块调用公开服务；不绕过服务直接改他人模型 |
| `workers/` | Celery 入口、outbox 派发、运行恢复 | 接收标识后重新读取数据库，不接受任意执行代码 |
| `workflows/` | LangGraph 的显式输入、状态、节点及输出 | 返回候选/产物，不拥有正式论文写权限 |
| `migrations/` | 版本化 schema 变更 | 不依赖会变化的业务 service；保持历史迁移可独立执行 |
| `tests/`、`scripts/` | 行为回归与统一开发入口 | 测试专用数据和连接，不读取开发者私人文件 |

`router` 负责参数解析、依赖和 HTTP 状态；`schemas` 定义输入/输出；`service` 实施规则与事务；`models` 定义数据库约束。需要复用 SQL 时才增加 `repository`，其方法只查询/flush，不能偷偷 commit。

## 3. Python 与依赖

1. 当前基线为 Python 3.13；精确版本由 `.python-version`、`pyproject.toml` 和实际验证共同确定。依赖以 `uv.lock` 为准，不抄参考仓库的浮动版本。
2. 仅在 `apps/api` 独立环境操作。新增依赖说明用途、替代选择、许可、是否触发网络/付费，再同步锁文件；普通同步使用 `uv sync --locked`，禁止用全局 pip 临时补包后声称可复现。
3. 新代码函数参数/返回值完整标注，使用 `UUID`、时区明确的 `datetime` 和窄枚举；输入 schema 拒绝未声明字段。仅项目名称等字段可按已声明规则 trim，导师反馈和原文不得全局 strip。
4. `Any`、`type: ignore` 只允许在第三方无类型边界，须范围最小并注明原因；不能全局关掉检查。禁止 `except Exception: pass`，可恢复异常明确分类，未预期异常统一转为不泄密的内部错误。
5. 同步数据库路由使用 `def`。异步适配器可以使用 `async`，但不能直接调用阻塞 SQLAlchemy/Redis；若未来转异步，作为独立架构变更连同 Session 生命周期和 worker 契约一起验证。

## 4. API 与契约

- 业务前缀固定 `/api/v1`；路径用复数资源名和 UUID。操作名称表达业务目的，不暴露数据库表结构；写操作不能使用 GET。
- 输入/输出均使用 Pydantic schema，不直接返回任意 ORM `__dict__`。成功返回资源或明确列表结构；新增、接受后台任务分别使用合适的 201/202。不要用 HTTP 200 包裹失败。
- 列表具有分页上限和稳定排序；禁止无界读取。时间采用 ISO 8601 UTC，字段名使用 `snake_case`；前端适配层负责与既有 camelCase 预览模型映射，不能直接把预览状态整包入库。
- 错误包含稳定 `code`、中文 `message`、`request_id`，错误外层结构以导出 OpenAPI 为准。401 表示认证失败，404 表示资源不存在，409 表示版本/幂等冲突，422 表示输入不合法，503 表示必要服务未就绪。
- 错误码采用 `MODULE_REASON`，由整合者集中检查重复和语义复用；新增码同时补契约和异常测试。客户端依赖 `code`，不能解析中文消息执行分支。
- 请求 ID 仅用于追踪，不作为用户身份、幂等键或授权依据；外部传入值必须验证长度与字符，不原样写入日志。
- API 变更同步导出并检查 OpenAPI；兼容新增字段仍需前后端联调。重命名、删字段、缩小允许值及改变状态语义必须说明迁移路径，不能静默破坏现有调用。
- 本轮服务令牌用于受控联调，缺配置拒绝业务请求。不得宣称已实现用户账户、会话撤销或项目归属校验；加入多用户访问前必须完成这些边界。

## 5. 事务、版本与数据保护

每个请求/后台执行独享 Session；Engine/Session 工厂可复用。业务 service 在最外层通过 `with session.begin()` 明确一次命令的事务，出错回滚；依赖退出只负责关闭，不能无条件提交。事务开始前避免无意查询触发 autobegin；复合命令只由一个外层服务拥有提交权。

更新必须将 `id` 与 `expected_version` 一起放入 UPDATE 条件，成功时递增版本，影响 0 行返回冲突或不存在。不能先在 Python 比较版本、再无条件更新；行锁/CAS 的选择应附 PostgreSQL 并发回归。数据库也应约束唯一性、外键、版本范围等不变量，不能只靠接口校验。

正式论文的后续写入服务必须在同一事务复验：基础版本、候选状态、选区、数字/引用/公式/锁定内容及重叠补丁。未经采纳不写正文；无法解析的对象保持锁定或拒绝。撤销保存可追溯新版本，不能删除历史。首轮项目元数据版本检查不代表上述论文保护已实现。

外部模型/网络调用不放在持有文档行锁的长事务内。先固定输入版本并登记任务，在事务外生成，落库时再次校验状态与执行令牌。金钱、数值和公式的精确语义按业务定义，禁止以不受控浮点转化改变论文数据。

## 6. 迁移管理

1. 迁移由本轮整合者统一分配，开发者先申报涉及表、约束和父 revision。只允许一个预期 head；不同 revision 名称仍可能形成多头，不能只比文件名。
2. 在明确的开发/测试库生成 `alembic revision --autogenerate -m "..."`，逐条审阅生成代码；列重命名、数据搬迁、默认值、索引和约束均要人工判断。不得直接使用自动生成结果覆盖真实数据。
3. 验证空库到 head、已有版本升级、`alembic check` 与元数据一致。需要保留的数据制作自制样例验证；离线 SQL 成功不能代替数据库实际执行。
4. 尚未共享且未执行的迁移可协调修改父节点；已共享/执行的历史迁移禁止重写，冲突由整合者设计后续或 merge revision，并验证顺序与 schema，不把两个 head 直接标为成功。
5. 应用启动不自动 `create_all`、升级或 stamp。测试可在隔离 SQLite 使用 `create_all` 加速，但真实集成必须走 Alembic。迁移失败停止并保留错误，不能自动 stamp 跳过。
6. 删除表/列、drop、清空、不可逆数据迁移及正式库 downgrade 先说明影响并遵守用户授权。仅一次性测试数据库内执行已声明的重建/回滚；禁止从普通应用连接推断它是测试库。数据迁移若不可安全 downgrade，明确拒绝并给前向修复方案。

## 7. 后台任务与编排

数据库为 Job 状态和产物事实来源，Redis 负责输送消息。创建 Job 与 outbox 必须在同一事务写入；数据库提交之前不得调用 `.delay()` 当作可靠派发。

| 阶段 | 必须保持的不变量 |
|---|---|
| 创建 | 幂等键与请求摘要绑定并有数据库唯一约束；同键同参返回同一任务，同键异参 409；未来多用户需加入身份/项目作用域 |
| 派发 | 小批量读取 outbox；发布失败可重试；消息发送后才记已发；发布成功但标记失败可能重发，消费端必须幂等 |
| 领取 | 条件更新状态并生成执行 token/租约；重复投递不能重复拥有执行权；每次执行使用新 Session |
| 执行 | 只接收允许的任务类型和 ID；数据库重新读取固定输入，外部调用设置超时；拒绝用户指定任意 Celery task 名 |
| 完成 | 按 job、token、状态再次条件写入；失败、取消、旧 token 结果不得覆盖新执行；产物和成功状态原子提交 |
| 取消 | 先持久化取消决定，后续结果复验；取消不保证远端模型立即停止，不能仅靠 revoke 当作数据保护 |
| 恢复 | 已过期租约可按策略重新认领；明确最大尝试、可重试错误和失败出口，不无限循环 |

至少一次投递不等于 exactly-once；`acks_late`、Celery task ID 或 Redis 去重本身都不能保证业务不重复。DB 唯一约束与条件提交才是最后防线。当前诊断任务是短任务；接入长任务前增加续租/心跳、超时、重试预算与故障注入验证。

LangGraph 负责图步骤，Celery 负责执行调度，业务服务负责最终状态与写权限。图状态类型明确，节点返回经过 schema 校验的候选；资料内容不能变成系统提示、执行代码或任意工具权限。初期诊断图不使用模型，不声称支持持久人工暂停；后续引入 interrupt 时必须增加持久 checkpointer、稳定 thread ID 与权限校验，验证重启恢复和重复恢复。中断节点恢复可能重跑，节点内副作用需幂等。

## 8. 设置、日志与安全边界

- 环境变量经 Settings 集中校验；只提交 `.env.example` 的空值/明显占位值，真实 `.env` 不入 Git。凭据使用 SecretStr 等受控类型，只在连接/比较时取真实值。
- 日志默认记录事件、路由模板、状态码、耗时、请求/任务 ID 和错误码；不记请求体、论文、导师原文、Authorization、完整连接串、模型输入或原始异常参数。
- 校验错误不能回显 Pydantic 输入值；未知错误不能将数据库 SQL、堆栈和凭据返回客户端。自制敏感标记样例应验证响应与日志都不泄露。
- CORS 使用明确来源，不能把 CORS 当身份验证；不在浏览器持久保存服务端管理密钥。服务令牌不可加入前端产物。
- 存活检查只表明进程可响应；就绪检查验证必要依赖及迁移状态，失败返回 503，不能把依赖不可用显示为健康。
- 文件存储后续使用服务端生成标识、路径根限制、大小/类型校验和摘要；不信任上传文件名，不让解析器访问任意路径/网络，不在本轮承诺已实现。

## 9. 验证与持续集成

在 `apps/api` 执行：

```powershell
uv sync --locked
uv run python scripts/check.py
uv run python scripts/check.py --integration
```

默认入口负责快测与静态/契约检查，集成入口要求显式测试连接与真实服务；具体环境变量、包含步骤及实际结果以 API README 和检查脚本为准。显式要求集成时，配置缺失必须失败，不能通过 skip 得到绿色结论。

| 验证层 | 覆盖 | 不能替代 |
|---|---|---|
| Ruff / mypy / 契约检查 | 格式、静态错误、类型、OpenAPI 漂移 | 运行期事务正确性 |
| 单元与 SQLite 快测 | 确定性逻辑、HTTP 错误、提交回滚、状态转换 | PostgreSQL 的锁、隔离级别、并发约束 |
| PostgreSQL 集成 | 真实迁移、CAS 竞争、唯一幂等、事务与 outbox | 真实 Redis/worker 链路 |
| Redis + Linux worker 集成 | HTTP 创建→outbox→消息→worker→数据库完成，重复/取消路径 | 真实模型质量或完整产品 AC |
| 产品场景 | 需求指定的输入、操作、恢复和跨页闭环 | 比赛材料与用户试用 |

CI 采用与本地相同入口和锁文件；PR 检查默认只读仓库权限，避免向不受信任贡献运行注入密钥。新增 CI 文件不等于远端实际执行，GitHub 成功必须取得运行结果。后端改动不无故重复完整前端检查；涉及公共契约或前端接入时运行相应前端门槛。

## 10. 开工、开发、审查、合并、收工

1. **开工**：读仓库规范与相关需求，检查 status/HEAD，保存[任务模板](templates/backend-task.md)；主会话串行确认文件/接口/迁移/错误码所有权。遵循[协作流程](multi-agent-workflow.md)，无需每个分支先提交 main 台账，也不为每个任务增加产品版号。
2. **设计**：写清正常及失败状态、事务范围、并发与取消行为、可执行验收；影响最终文档 schema 的未知点先做样例验证。接口变更先通知依赖方，公共文件只交整合者修改。
3. **开发**：在认领范围按纵切片实现；优先独立 worktree。共享目录禁止切换主检出、reset、clean 或覆盖他人改动；扩大范围先更新所有权。每次里程碑记录真实命令和失败修复。
4. **审查**：对照需求而非只看 diff 是否美观；重点检查未采纳写入、版本竞争、跨项目访问、日志泄密、迁移破坏、重复任务和测试假通过。独立 Agent 可审查，最终整合者仍需核实。
5. **提交与合并**：按真实迭代提交，显式 `git add <本任务文件>` 后审阅暂存差异。推送前 fetch、对已有跟踪分支 rebase、检查迁移 head/错误码冲突并复验；冲突解决要保留双方业务意图，不只消除标记。遵循 [CONTRIBUTING](../../CONTRIBUTING.md)，不 force push，不自行公开或部署。
6. **收工**：按 AC 列已通过/失败/未执行，记录环境、命令、退出码、未完成边界、原始证据位置及真实提交 SHA；未提交明确写未提交。未集成只能标待审/暂停/阻塞，整合确认后再释放占用。留下下一个接手者可直接运行的复现和下一步。

## 11. 合并检查单

- [ ] 每条范围内需求有入口、状态、失败恢复、验收及证据；未实现项没有被写成不适用。
- [ ] 服务事务、数据库约束、CAS、幂等及取消边界与测试相符；无模型绕过正式写入入口。
- [ ] API、错误码、配置示例、OpenAPI、迁移与锁文件一致；无无关公共文件改动。
- [ ] 静态/快测实际通过；涉及数据库和队列的真实集成门槛通过或明确阻断，不能把阻断标为功能 Done。
- [ ] 日志/响应不含凭据与真实论文；第三方来源和许可有记录。
- [ ] README、已知限制、开发证据和交接已更新；没有虚构对话、提交、远端 CI、模型效果或用户认可。
