# 前端逐模块接入说明

目标是让现有 Vue 页面沿用设计与交互，在同一契约下分别使用 Mock 与 HTTP 服务。早期范围和验收编号见[接入计划](frontend-integration-plan.md)，当前字段和业务规则见[数据契约规范](data-contracts.md)。

真实联调已覆盖项目元数据、正式稿和诊断任务。复现方式见[本地运行](local-runtime.md)，当前验收范围分别见[正文持久化记录](../evidence/sessions/document-persistence.md)和[长任务记录](../evidence/sessions/job-reliability.md)。

## 1. 模式与数据范围

| `VITE_SERVICE_MODE` | 页面与服务 | 数据事实来源 |
|---|---|---|
| `preview`（默认） | 保留现有完整本地预览和原有项目/任务交互 | 浏览器工作区；原有本地预览服务 |
| `mock` | 项目、正式稿与诊断任务通过同一异步服务接口 | 明确标注的内存模拟服务，本机内容继续由工作区管理 |
| `http` | 同接入组件调用真实 API | 项目元数据、正式稿和诊断任务以服务器为准。本机原稿、规划、资料及反馈继续保存在浏览器 |

模式在开发启动或构建时明确选择。请求失败、401、服务器未就绪或响应无效都不能自动切换 Mock。接口模式不是将十二个页面全部切成服务器持久化；本轮只完成约定切片，未接入的业务必须继续标明本地范围。

Mock 在应用会话内跨页共享，整页刷新会重建内存服务。本机原稿和规划沿用浏览器工作区保存，正式稿草稿独立保存在 IndexedDB。

原有完整项目表单仍供 preview 使用。接口模式中的创建/改名只提交 `name` 与必要版本；不能将截止日、阶段、个人规划、归档、正文或资料作为额外字段发给当前 API，也不能在名称成功后提示“整个项目已同步”。不把现有 `PreviewProject` 复制成后端通用 JSON 表。

## 2. 分层与文件职责

| 位置 | 职责 |
|---|---|
| `apps/api/openapi.json` | 实际后端契约快照，来自 Pydantic/路由导出 |
| `apps/web/scripts/generate-api.mjs` | 从契约生成 TypeScript DTO 和运行时 schema，检查生成漂移 |
| `apps/web/src/services/` | 公共服务接口、HTTP/Mock、统一错误、响应校验与映射 |
| `src/services/runtime.ts` | 创建当前模式的服务实例，统一服务实例标识，不在页面分散判断环境 |
| `src/lab/components/integration/` | 项目、诊断任务与正式稿接入组件 |
| `ScreenProjects.vue` / `ScreenWrite.vue` / `ScreenJobs.vue` | 沿用现有页面路径和布局。写作台按来源切换，任务中心与全局托盘共用服务任务状态 |
| `remoteDocuments.ts` / `documentDrafts.ts` | 确认服务端正式稿、版本冲突和独立浏览器草稿 |
| `previewWorkspace.ts` / `previewBackup.ts` | 本机工作区和服务项目的明确关联、恢复校验；不承担通用 HTTP 请求 |

公共服务层返回 Promise，接收可选 AbortSignal。页面依赖服务接口而非某个 Mock 函数或直接 fetch；HTTP 与 Mock 的请求/响应相同。业务错误统一转换，页面只关心结果和可执行恢复动作。生成文件不手改，字段变化回到后端契约源。

## 3. 生成与变更流程

从后端目录导出真实契约，再从前端目录生成。命令不要求后端服务已启动，但后端 Python 依赖必须可用；缺包时停止，不手写假 OpenAPI：

```powershell
# apps/api
uv run python scripts/export_openapi.py

# apps/web
node scripts/generate-api.mjs
node scripts/generate-api.mjs --check
```

生成器只支持已声明的 schema 子集；遇到不能正确表达的结构必须失败。扩展 schema 时同时扩展生成器与运行时校验测试，不能把未知结构转成 `any`。TypeScript 类型只约束编译期，所有外部响应还需运行时结构校验；语义约束仍由领域服务和对应回归承担。

变更顺序：需求/AC与字段表 → 后端 schema/接口 → OpenAPI → 生成产物 → Mock/HTTP/映射 → 页面与合同测试 → 实际服务验收。需要改变共同协议的两个 Agent 先确认接口再各自实现，公共契约文件只由整合者落地。

## 4. HTTP 与访问凭据

本轮采用同源开发代理：浏览器访问相对 API 路径，开发服务器连接明确配置的后端，并在服务器侧取得临时联调令牌。私密令牌不使用 `VITE_` 前缀，不放入源码、前端构建、localStorage、备份或错误提示；实际代理参数以工程配置和 `.env.example` 为准。

在 `apps/web` 使用 `.env.example` 作为本地配置起点；已有 `.env.local` 时先编辑现有文件，不覆盖。当前配置如下：

| 环境变量 | 作用与值 |
|---|---|
| `VITE_SERVICE_MODE` | `preview`、`mock` 或 `http`，默认 `preview` |
| `VITE_API_BASE_URL` | 浏览器同源路径，首轮 `/api/v1` |
| `VITE_API_INSTANCE` | 公开稳定实例 ID，例如 `local-api`；首字符为字母/数字，其后可含点、下划线、横杠，总长 1—64；HTTP 模式必须明确配置 |
| `TP_API_TARGET` | 仅开发服务器读取，首轮 `http://127.0.0.1:8000`；仅允许本机 HTTP 目标 |
| `TP_API_TOKEN` | 仅开发服务器读取，至少 32 字符且与后端配置一致；示例留空 |

前端开发命令仍为 `vp dev --host 127.0.0.1`。选择 mock 无需 API 服务；选择 http 前先按[后端 README](../../apps/api/README.md)完成依赖、迁移和服务启动。Vite 仅在开发 serve 的 `/api/v1` 代理中注入 Authorization；普通静态 build 不包含令牌，也不会自动提供代理。不得通过新增 `VITE_API_TOKEN` 解决静态部署认证问题。

服务实例标识是非秘密的命名空间，用于区分本机缓存关联。切换后端目标时也要切换对应实例标识，不把代理 URL 相同理解为数据来源相同。它不是服务端签发的身份或权限凭据，不能代替资源授权。

开发代理仅用于本机受控联调，不能冒充账户登录、会话失效处理或生产网关。发布前仍需完成用户身份、项目归属和服务端授权；静态离线 HTML 不具备开发代理能力。HTTP 模式无法访问服务时保留错误与草稿，不回退到本地成功提示。

## 5. 项目目录到本机工作区

项目目录的 API DTO 只提供服务端项目身份、名称、元数据版本与时间。页面展示可映射为 `title`，但必须保留原始 `version` 供后续改名。

用户明确“打开”接口项目时：

1. 按当前服务实例与远端项目 ID 查找已有 `remoteBinding`。
2. 找到时复用原本机项目，保留本地 ID、正文、历史、计划、资料及反馈；仅更新已明确从服务端取得的名称和绑定元数据。
3. 未找到时创建独立本机工作区并记录关联；不将其他本机项目自动上传或凭名称合并。
4. 打开该工作区。诊断任务与正式稿服务均使用关联的远端项目 ID，本机原稿继续按其本机 ID 保存。

`remoteBinding` 的当前结构为 `sourceKey/projectId/metadataVersion/createdAt/updatedAt`，对应服务实例命名空间、服务端项目 UUID、元数据版本及服务器时间。`sourceKey` 由服务工厂生成，不由页面根据名称拼接；绑定不含访问令牌。项目元数据版本与 `document.version` 独立；正文在本机编辑不会自动增改远端项目版本。名称更新请求成功后才更新服务器确认快照；409 时保留用户输入，刷新远端信息并重新决定，不自动改版本重发。

本地工作区正常刷新可保留合法关联；从 JSON 备份恢复为新项目副本时移除远端关联，避免副本默认操作原服务器资源。无法解析或服务实例不匹配的关联不能自动修补成另一个有效 ID。

## 6. 诊断任务与页面生命周期

任务中心和全局托盘共享匹配当前服务实例、当前关联项目的任务读写状态。没有关联时可前往项目目录。两处保留本机任务及按来源定位的详情入口。

创建诊断任务固定项目、kind 与幂等键。请求结果未知时，本标签页保留该服务和项目的未确认键，重发确认沿用同键同参。确认后清除。失败或取消记录上的「重新运行」使用新键创建新任务，原记录仍保留。活跃数取 `status=queued&status=running` 过滤后的服务端总数，分页列表用于目录，内部任务标识和诊断码可在详情查看。

| 触发 | 行为 |
|---|---|
| 工作区切换关联项目 | 取消旧查询、清理旧展示上下文，按当前远端项目重新读取 |
| 查询刷新 | 使用请求序号或同等机制拒绝迟到结果；避免重叠轮询覆盖新结果 |
| 在工作区跨页 | 全局托盘继续查询当前项目的活跃任务，离开工作区后停止浏览器查询 |
| 用户点击取消 | 发送业务取消命令，等待服务端确认或重查最终状态 |
| 断线/请求超时 | 显示未取得最新状态；不推断任务失败、成功或取消 |
| 返回成功状态 | 显式将 `succeeded` 映射为展示 `done`；不伪造 `partial` |

服务端终态 `JOB_EXECUTION_TIMEOUT`、`JOB_RESULT_INVALID` 分别显示为执行超时、结果未通过校验。请求层超时保留最后确认状态并允许重查。真实任务范围为诊断，解析、评审、导出与模型调用按各自模块接入。

## 正式稿与本机原稿

已关联项目的写作台沿用同一编辑器切换来源，本机原稿和本机历史维持原身份。服务明确返回当前项目无正式稿时才提供主动导入，转入的结构按正式稿 v1 保存。已有正式稿、服务查询失败或结构无法转换时保留本机原稿。

编辑正式稿时，草稿按服务实例、远端项目、文档及本机工作区隔离，并保留各自的基础版本和草稿身份。IndexedDB 保留草稿，用户点击保存或使用快捷键才按固定版本提交快照。保存等待确认期间的新改动继续留在草稿。409 或请求结果未知时先重查，确认前保留草稿，用户可以归档现有草稿并载入新版。草稿存储失败可下载当前草稿。

正式稿历史分页读取摘要，选定版本后单独读取并只读对比。正式历史链接包含服务、项目、文档和版本，已有本机版本链接仍定位本机历史。正式稿保护、采纳、撤销及历史恢复写入在 SG-04 接入，相关本机操作维持其本机范围。

## 7. 交互与动效

页面接入和交付检查按[页面功能设计与覆盖](../design/page-functional-design.md)执行。

接入组件复用现有 Tp 控件、语义令牌和共享过渡。表单打开/退出、列表新增、详情、加载/失败状态必须实际使用动效；减弱模式保留信息并按现有规范限制时长。稳定资源 ID 用作列表 key；异步结果不重建正文编辑器。

提交期间阻止同一命令的重复发送，取消查询仍需防迟到回调；表单失败保留输入。退出期间停止交互，快速重开不能被旧关闭回调影响。动画不延迟业务状态提交，不为了播放完成效果先显示虚假成功。

## 8. 验证与交接

| 层次 | 必须覆盖 | 不能声称 |
|---|---|---|
| 契约生成 | schema 子集、未知结构拒绝、生成漂移、类型与运行时校验 | 生成成功等于业务正确 |
| 公共服务合同 | 项目元数据 CAS、正文导入唯一与版本 CAS、历史只读、正文专用预算、Job 幂等/状态、分页、错误、取消与超时 | 注入 fetch 的测试等于真实 HTTP 已通 |
| 工作区关联 | 本地 ID/正文/模块保留、实例隔离、重复打开复用、备份副本去绑定 | 有关联字段等于已完成账户权限 |
| 前端页面 | preview 原交互、Mock 接入流程、正式稿/本机来源隔离、独立草稿、任务托盘与中心一致、冲突恢复、迟到响应及实际动效 | Mock 浏览器通过等于真实后端可用 |
| 后端服务 | Job 列表过滤/分页、元数据契约、取消/幂等/事务 | SQLite 等于 PostgreSQL 并发验收 |
| 真实联调 | 同源代理、认证、API/数据库/Redis/worker、刷新恢复 | 未运行的真实服务检查已通过 |

前端执行现有 `vp run check`、`vp test run`、`vp build`、`vp run test:e2e`，并补生成检查；HTTP/Mock 模式的实际启动参数与结果记录在本轮证据。前端仅 Mock 可运行、HTTP 被环境阻断时，保留明确分项结论，不把缺服务作为静默跳过的成功条件。

完成后更新当前实现范围、契约、未接入字段与验收结果。按照[main 流程](main-workflow.md)保存实际小步提交；工作区/Git/网络阻断如实交接，不重复打包其他会话成果。后续模块沿用本文件与[字段模板](data-contracts.md)，无需等待整套后端完成后再统一接入。
