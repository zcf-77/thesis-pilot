# 单人 AI 开发规范

适用项目：ThesisPilot。状态：初始规范；不是已完成开发的证明。官方硬性要求见 [比赛台账](../competition/requirements.md)，产品通过条件见 [场景验收](../product/acceptance.md)。

## 1. 责任与原则

人类负责人决定需求、架构取舍、验收与发布；AI 承担分析、生成、审查和验证辅助。使用多个 AI 角色仍是个人主导项目，不把工具数量作为创新点，也不伪称多人用户研究。

质量目标是有用、稳定、可解释、可复现、证据真实；“完美”和“保证获奖”不作为验收条件。所有目标必须落到检查项，尚未检查就保留未执行状态。

## 2. 开始条件（Ready）

每个任务进入实现前必须具备：

- 问题和用户情境：谁要完成什么，当前困难是什么。
- 范围与非目标：本次允许修改的文件/模块，不做什么。
- 对应 `AC-*`、必要时 `REQ-*`，明确正常、异常、边界场景。
- 数据与权限约束：能读取什么、能生成什么、何时允许落库。
- 验证办法：具体命令或人工操作、预期结果、失败标准。
- 关键不确定项：例如 DOCX 公式保持是否可行；先做小样验证，再承诺产品范围。

## 3. 一次真实迭代的步骤

1. **读取上下文**：工作区状态、相关需求、当前实现、最近变更与已知失败；上下文以文件和版本为准。
2. **固定意图**：使用 [任务模板](../evidence/templates/task.md) 定义目标、约束与验收，不要求一次生成整套产品。
3. **设计与取舍**：先说明数据流、状态变化、风险和最小改动；技术选择记录理由，已有决定改变时写明原因。
4. **生成实现**：按功能切片推进，一轮只解决可验证范围，避免未验证的层层生成。
5. **审阅**：检查意图是否对齐、数据是否越权、失败时是否破坏状态、是否引入未授权付费或网络依赖。
6. **实际验证**：运行编译/类型检查、相关自动化测试、必要的端到端或接口操作。记录命令、退出码、原始输出和检查范围。
7. **真实纠错**：将实际失败和最小复现输入交给 AI，记录原因假设、修改及复测。不为凑比赛材料故意造 Bug。
8. **提交与归档**：只提交本轮文件；原始对话、验证和代码关联到会话索引，更新状态及已知限制。

## 4. 提示词与上下文约定

任务提示词建议包含：目标、相关文件、输入样例、输出契约、不可变规则、允许编辑范围、验收方法、停止条件。不要把整份敏感论文发给所有开发工具；优先用自制最小样例复现。

上下文过长时可以生成交接摘要，但要关联原记录与代码版本；摘要不能替代原始证据。不要把 AI 的解释直接当成事实，尤其是库能力、比赛要求、模型准确率和运行环境。

编程 AI 对话用于证明开发过程；应用内智能体调用日志用于解释产品行为。两类证据分别存放，不混计三条完整开发 Prompt 链。

## 5. 测试分层

| 层级 | 应检查的内容 | 完成标准 |
|---|---|---|
| 文档/契约 | 链接、要求与验收编号、来源完整性 | 当前仓库校验器通过；不代表产品验收 |
| 静态检查与构建 | 类型、依赖、编译、必要安全检查 | 实际命令成功；无因缺环境而跳过的关键检查 |
| 确定性单元测试 | 保护项、补丁范围、依赖环、日期约束 | 正常与违规输入均覆盖，异常不得静默写入 |
| 数据/接口集成 | 版本比较、原子采纳、重试、撤销、重启恢复 | 使用真实数据库或等价集成环境验证，不以空 Mock 代替 |
| 端到端 | 导入→反馈→任务→修订→审阅→导出 | 在声明支持的样例上真实操作，保存录屏/截图与版本 |
| 模型评估 | 实际选定模型的建议质量、错误结构、提示注入 | 与固定响应回放分开，注明模型、样例、参数和失败 |
| 用户验证 | 3—5 位目标用户的任务完成情况 | 实际招募、授权与记录；未完成不得填满意率 |

不要为纯文案调整堆砌镜像测试；本项目核心的数据保护、版本和恢复逻辑必须有回归测试。具体测试命令在选定技术栈并实际运行后加入 README；不得预填“全部通过”。

## 6. 完成条件（Done）

- 对应 AC 的正常和异常流程已执行，有结果、有缺陷记录、有必要复测。
- 原文与历史没有被未确认写入破坏；重试、取消、超时、陈旧候选有确定行为。
- 对应对话和提交可追溯；至少三条完整核心链在参赛前逐条审阅。
- 用户可理解加载、失败、待确认和不支持状态；不靠大量说明文字补救交互。
- 更新环境、数据格式、依赖许可、已知限制与复现说明。
- 功能级 Done 不等于整项目 Done；参赛前额外检查视频、PDF、评审权限、最终回执。

## 7. 变更与发布控制

新增功能必须说明服务哪项痛点和评分维度；超过时间预算优先削减外围功能，不能削减原文保护、真实证据与复现。

产品发布阻断项见验收文档。仓库 push 与应用上线是不同动作；本次仅授权创建并推送私有代码仓库，不自动授权服务器部署或公开用户数据。代码合并、推送与变更权限遵循根目录指令。

## 8. 证据诚实规则

禁止补写虚构 Prompt、倒签提交、抄用别人的成品、伪造测试和试用。模型输出不能替代真实实验和参考文献来源。评审演示中的回放与模拟数据必须标注，失败与限制如实呈现。

为了可复现，记录代码版本、依赖锁、模型与配置、数据样例、运行步骤和原始输出。相同提示词不保证再次生成相同代码；通过真实版本与演进记录解释开发，而不承诺模型输出逐字一致。
