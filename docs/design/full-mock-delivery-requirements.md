# 毕设智途：全套 Mock 前端交付与验收要求

版本：2026-11-11；2026-11-14 补充功能设计前置与全局风格要求。功能范围见《全套 Mock 前端功能需求》的 F01—F20。

## 1. 交付目标

设计并实现一套可运行、可操作、组件化的 Vue Mock 前端，覆盖全部功能模块与业务流程，为后续 FastAPI 和真实 AI 接入保留清晰边界。

从现有 `apps/web` 的 Vue 设计展台继续演进，统一遵循 [DESIGN-SPEC](../../apps/web/docs/design/DESIGN-SPEC.md) 及配套组件；旧原型仅供历史追溯。F01—F20 是能力清单，不意味着必须制作二十个页面；页面拆合依据完整功能流程决定，视觉与交互保持全局统一。

必须先完成本轮涉及功能的需求映射、流程、输入/输出、状态及跨模块关系，再进行视觉页面和 Vue 实现。未完成这一步不进入页面设计；阶段性范围之外的功能继续保留在覆盖清单，不擅自删除。具体执行见 [页面功能设计与覆盖](page-functional-design.md)。

单独的图片、Figma 文件、静态 HTML 或只有跳转的演示，不能替代本轮 Vue 前端交付。设计文件可以作为补充。

## 3. 工程要求

### 3.1 技术栈与运行入口

- 使用 Vue 3、TypeScript、Vue Router、Pinia、Tailwind CSS、daisyUI。
- 使用 Vite+ 统一管理工程和命令，底层 pnpm；只维护有效的 pnpm 锁文件。
- Node 版本以项目 `.node-version` 固定，工具链及依赖版本在 package.json 与锁文件中保持一致。
- 统一入口包含 `vp install --frozen-lockfile`、`vp dev`、`vp run check`、`vp build` 和 `vp run test:e2e`；具体脚本必须真实可运行。
- 静态检查包含 Vite+ 的 Oxlint/Oxfmt，以及 Vue 专属类型检查。不能因更换工具而取消 Vue 检查。
- 端到端测试用 Playwright，经 Vite+ 任务调用。`vp test` 的 Vitest 测试与 Playwright 浏览器测试分开，不把空套件当作通过。
- 不将真实 API 地址、访问令牌、用户论文或密钥嵌入源码和样例。

### 3.2 组件化与可复用性

- 业务展示组件、编辑器适配、共享状态、服务访问、样例数据分离。
- 组件通过明确 props/emits 或受控状态契约协作，不靠直接操作其他组件 DOM 或全局变量修改业务数据。
- 表单与通用状态交互可复用；不要将所有模块堆进一个超大组件，也不要为每个文本元素过度拆分。
- 文献、修订审阅、评审报告、计划调整、任务、资料版本、四库表单和运行状态等能力具有独立边界。
- 论文编辑使用同一个项目文档状态；AI 模式和模块切换不能销毁未保存编辑或创建竞争正文副本。
- 外观和主题代码与业务规则分离；交付中说明组件需要的样式及依赖，以便在正式项目直接引用。

### 3.3 服务和数据契约

- Mock 和未来真实实现使用同一层服务接口。展示组件不得直接写固定 AI 回复、固定分数或假成功状态。
- 项目、文档、资料、计划、配置和报告等对象的 ID 与版本关系一致。
- 接口需要定义正常返回、错误、取消、过期、冲突和部分结果，不能只定义成功数据。
- 模拟服务应有可控且可重复的场景，不依赖不可复现的随机数制造通过结果。
- 同一操作在相关模块中产生一致结果，例如项目采用的新模板版本能在要求检查和评审输入中看到。
- 可选择 IndexedDB 或其他适当的浏览器存储；具体实现由交付方决定，但必须披露容量、刷新和重置边界。
- 重置样例不得无提示覆盖用户编辑；不设计真实密钥的浏览器明文存储。

建议的数据对象至少覆盖：Project、WorkflowVersion、DocumentVersion、TemplateVersion、RequirementVersion、MaterialVersion、Task、EvidenceLink、PlanVersion、Feedback、Conversation、RevisionCandidate、RevisionDecision、ReviewRun、ReviewReport、Notification、AgentVersion、PromptVersion、ApiConfigVersion、ModelConfigVersion、Job。命名可调整，但不能丢失对应职责和版本关联。

## 4. Tiptap 引擎交接要求

### 4.1 使用的引擎

本轮使用 **Tiptap 3.33.1**，包含以下依赖：

| 包 | 用途 |
|---|---|
| `@tiptap/vue-3` | Vue 编辑器实例与 EditorContent；可导出编辑器相关类型 |
| `@tiptap/pm` | ProseMirror 相关结构与事务能力 |
| `@tiptap/starter-kit` | 标题、段落、常用标记、列表、历史等基础能力 |
| `@tiptap/extension-table` | TableKit 及基础表格能力 |

同组扩展版本应兼容并锁定。需要新增图片、公式、锁定对象等扩展时，核对许可与能力并记录原因；不默认采用付费服务，不把安装扩展等同于通过兼容性验证。

Tiptap 是编辑内核，不是完整 Word 排版、分页和 DOCX 转换服务。编辑器业务交互先依据功能需求设计，Vue 外壳复用当前设计规范与组件；不继承已退役的旧原型界面。

### 4.2 必需适配能力

交付可供业务层调用的编辑器适配接口，具体函数名可自行命名，必须覆盖以下语义：

| 能力 | 契约要求 |
|---|---|
| 获取/载入文档 | 结构化 JSON、schema 版本、当前文档版本；拒绝无法解释的结构 |
| 读取上下文 | 项目、文档版本、章节、选区范围及选区内容；区分光标与非空选区 |
| 章节定位 | 使用稳定业务标识和当前文档映射，不仅依靠屏幕坐标 |
| 监听编辑 | 正文变化、选区变化、保存状态与内容版本更新 |
| 生成候选输入 | 固定基础版本、作用范围、原始片段和保护项 |
| 校验与应用 | 校验版本、范围、保护项及冲突后应用；不将模型字符串直接覆盖正文 |
| 历史与恢复 | 撤销、重做、查看版本、恢复版本且保留操作记录 |
| 支持范围 | 对未实现的公式、图像、目录、分页或其他对象返回明确限制 |

选区位置应考虑文档结构和 Unicode，不能将纯文本下标、UTF-16 偏移、表格单元格位置与页面坐标混用。候选应用前必须再次检查当前状态；内容不匹配时重新审阅。

### 4.3 不作为已完成能力的内容

- 纸张外观不证明真实分页。
- 显示模板样例不证明学校模板合规。
- 渲染公式示例不证明复杂公式可编辑或可无损导出。
- 浏览器版本检查不证明服务器数据库事务或多设备并发安全。
- 普通 HTML/JSON 文件不等同于 DOCX；不得伪造扩展名或 MIME 类型。

## 5. Mock 场景交付要求

至少提供可单独进入或触发的以下场景。场景开关用于设计验收，不要求嵌入正式学生流程。

| 场景组 | 必须覆盖的差异 |
|---|---|
| 项目与个人规划 | 空项目、已有论文、有规划、未填写规划、不同项目隔离 |
| 资料与模板 | 上传处理中、解析成功、部分识别、解析失败、重复上传、新版本 |
| 论文要求 | 可确定检查、语义建议、来源缺失、互相矛盾、尚不能判定 |
| AI 与修订 | 等待、生成成功、无效结构、保护违规、越界、拒绝、采纳、撤销 |
| 并发与取消 | 基础版本已变、重叠候选、重复响应、取消后迟到、重试 |
| 进度计划 | 正常推进、延期、无可观察进展、章节完成、阶段完成、循环依赖、无可行解 |
| 导师意见 | 明确意见、歧义、无法定位、学生纠正、处理证据变化 |
| 文献 | 有结果、无结果、仅题录、仅摘要、已取得全文、来源无法核实 |
| 评审 | 整篇、指定章节、证据不足、未检查项、旧稿报告、报告导出失败 |
| 四库管理 | 新增、编辑、停用、历史版本、缺变量、无效关联、模拟认证/限流/超时 |
| 数据恢复 | 刷新恢复、存储失败、有效备份恢复、损坏备份拒绝、重置样例 |

样例资料使用自制或获授权内容，演示论文和规范不能伪称来自真实学校。报告分数、接口连通性和文献结果说明模拟性质即可，不在每个正常操作中重复堆叠提示。

## 6. 验收清单

以下是全套 Mock 前端的验收，不等同于正式后端、真实模型或赛事验收。每项记录实际结果、执行步骤和证据；未实现不得标为通过。

| 编号 | 验收项 | 可判定结果 |
|---|---|---|
| M01 | 工程复现 | 干净环境按说明使用 Vite+ 安装、启动、检查和构建，依赖锁一致 |
| M02 | 全模块覆盖 | F01—F20 有对应可操作入口和闭环；无无效按钮、假提交或只做成功提示的功能 |
| M03 | 项目与上下文 | 新建/切换/归档恢复可用，两个项目的正文、任务、资料和会话不串用 |
| M04 | 真编辑 | Tiptap 支持声明的输入、选择、格式、表格、撤销重做；模块切换不丢稿 |
| M05 | 修订决定权 | 生成和拒绝不改正文，采纳只应用允许片段，撤销和版本历史真实对应 |
| M06 | 保护与冲突 | 已支持对象的数字/引用/公式/锁定/范围检查实际执行；旧版本、重叠、无效结构被拒绝 |
| M07 | 取消与重复 | 重复点击/响应不重复应用，取消后迟到不生效，失败保留原数据且可重试 |
| M08 | AI 模式与会话 | 综合和专业模式、多助手沟通保持上下文及草稿，每次调用可确定范围 |
| M09 | 计划闭环 | 学生确认后更新进度；计划候选采纳前不变；依赖与硬截止冲突可解释 |
| M10 | 主动辅助 | 重大事件有依据，去重/冷却/延后/忽略有效，日常输入不持续打断 |
| M11 | 反馈闭环 | 原文、拆解、纠正、任务及修改证据关联可追溯，不冒充导师认可 |
| M12 | 文件与模板 | 上传及模拟解析状态可操作，原件/解析/诊断/版本关联完整，无发布核对门槛 |
| M13 | 要求管理 | 来源定位和修正版本可用，硬规则与语义判断区分，未知或冲突不伪装为合规 |
| M14 | 文献边界 | 内容获取范围清楚，来源可追溯，引用经采纳写入，不伪造检索和全文阅读 |
| M15 | 仅评审 | 整篇/章节入口可用，报告有依据与未检查项；正文、计划及完成状态不变 |
| M16 | 四库关联 | 四库增改停用与版本可用，无效关联被识别，运行使用具体配置快照 |
| M17 | 下载与恢复 | 支持格式的真实文件可打开，内容对应当前数据；有效备份可恢复，损坏备份不破坏数据 |
| M18 | 异常与基本可用性 | 关键功能可键盘操作，输入与控件有可访问名称；适用窗口尺寸下无遮挡或不可达操作 |
| M19 | 可复用性 | 展示组件、状态、编辑器、Mock 服务和 fixtures 分离；替换服务不要求重写界面 |
| M20 | 诚实交付 | Mock/真实能力边界、未实现项、依赖许可及验证限制明确；无虚构模型或产品效果证据 |

M18 仅要求实际可用，不规定屏幕断点、排版方式或外观。

自动化优先覆盖采纳与撤销、旧版本阻断、保护项、取消后迟到、计划约束、仅评审不写入、跨项目隔离和恢复。视觉及复杂对象检查记录实际人工/浏览器检查范围，不以编译成功替代。

## 8. 给设计智能体的任务说明

请根据配套功能需求，先完成功能流程和状态设计，再以现有 Vue 设计展台演进“毕设智途”的完整 Mock 前端，覆盖 F01—F20，按 D01—D08 交付并逐项记录 M01—M20 验收。视觉、排版、组件与导航遵循当前 DESIGN-SPEC，全局统一；已退役旧原型不作为实现依据。

使用 Vue 3、TypeScript、Vue Router、Pinia、Tailwind CSS、daisyUI 和 Tiptap 3.33.1；工程统一使用 Vite+，底层 pnpm。交付可继续接入 FastAPI 的组件化源码，保持编辑器、状态、服务、样例数据与展示组件分离。

以“主动辅助、重要节点介入、学生最终决定”为业务原则。真实实现前端编辑、状态变化、候选采纳、版本保护和可恢复流程；AI、解析、检索、评审等通过可控模拟服务提供，明确模拟边界。不要用固定截图、假成功提示或伪造文件代替功能。

本轮不实现租户、学校层级、权限体系、院长审批、教师独立账号、资料核对发布、规则更新影响或真实后端。遇到会改变功能范围或需要替换编辑引擎的重大问题，先说明问题与取舍；不要自行删减已要求的模块。
