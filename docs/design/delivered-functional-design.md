# 交付设计的功能与模块设计基线

更新：2026-11-14。本文将已交付设计中的功能职责、模块交互、状态和验收要求纳入当前项目文档。它是功能设计依据，不是“已实现”声明；现状和缺口另见[实现审计](design-implementation-audit.md)。

## 1. 来源、优先级和覆盖边界

1. 用户当前确认优先：Vue工程、按功能先设计再实现、全局统一；导师反馈仅粘贴文字；写作工作区参照交付图的功能布局并显示阶段进度。
2. 已有[F01—F20需求](full-mock-functional-requirements.md)和[D01—D08/M01—M20交付要求](full-mock-delivery-requirements.md)继续有效。不能因某页只做了少量功能，就反向削减需求。
3. 交付设计的功能依据包括 `DESIGN-SPEC`、布局/业务/设计语法页面、写作/今日场景、业务组件接口和状态类型；[来源提取台账](delivery-source-functional-inventory.md)记录原包与当前文件的对应、锚点和来源性质。
4. 三种外壳的备选方案、主题取舍、图片中的固定日期/字数/分数/已完成章数，不能自动成为业务事实。实际状态必须由项目数据、来源版本和学生决定产生。
5. 本文覆盖完整Mock前端；真实AI、真实身份服务、正式后端和完整DOCX转换不在本轮要求内。允许模拟服务，不允许用说明文字、无动作按钮或固定成功结果替代所要求的前端操作。

## 2. 七个工作空间的功能职责

| 空间 | 必须承载的功能 | 主要输入与输出 | 决定权与跨页关系 |
|---|---|---|---|
| 今日 | 项目/阶段、缺项与下一步、任务进度、重大节点、等你决定 | 绑定流程、期限、任务证据、修订/计划候选、歧义反馈→待办聚合与明确跳转 | 进度来自学生确认；进入具体候选审阅，不能在首页替学生采纳 |
| 写作 | 单一正文、章节目录、选区、支持对象、保存状态、审阅/版本/副驾 | 正文与版本、当前章节/选区、资料和要求→编辑或候选；明确采纳才形成正式修订 | 查询文献/评审/配置后仍返回同一份正文；只读查看和正式编辑必须区分 |
| 计划 | 阶段要求、任务增改/排序/依赖、个人规划、证据核验、返工、调整候选 | 期限、依赖、产物版本及确认→进度、冲突说明、待决定的计划变更 | 证据失效需要复核；候选采纳前不变计划；实际事件关联主动提醒 |
| 资料 | 原件/版本、解析状态与纠正、模板/要求、文献检索及来源 | 实际文件或自制样例、原始规则、检索范围→版本化资料及上下文 | 上传直接解析保存版本，不加核对发布；绑定模板不自动改正文 |
| 反馈 | 仅粘贴原话、整理/纠正、歧义与定位、任务/修改证据、处理历史 | 原话与录入时间→待核对条目、明确关联与学生处理状态 | 原文不改；学生处理不代表导师认可；任务和证据不另造一套状态 |
| 评审 | 整篇/章节、固定版本运行、问题/依据/分项分数/未知项、报告历史及导出 | 正文、模板、要求、量表、配置快照→只读报告与定位 | 不改变正文/任务/计划；请求修订是另一个明确操作 |
| 配置 | 四库、流程、业务字典、提醒参数、演示会话、任务诊断、测试场景 | 版本化配置、变量/能力/关联约束→可运行配置与诊断快照 | 不上传任意执行代码，不让提示词或模型配置扩大正式写入权限 |

### 四种进度不可混用

- 阶段进度：在流程中的位置及已确认阶段，不代表论文质量。
- 阶段时间进度：当前阶段已用时间占阶段时间区间的比例，见交付样张 `SceneToday.vue:41`。缺起止日期时显示未知；不能用任务完成率或剩余天数替代。
- 任务进度：满足证据核验后的学生确认数量/比例；返工或证据过期需要明确复核。
- 字数目标：当前统计口径下的字符量与绑定规则目标；缺规则时显示未知，不默认12,000字。

时间剩余/逾期另由项目或阶段截止计算；示例“44天”不是默认业务值。

## 5. 完整业务流程和交接契约

| 流程 | 必须实际串通的步骤 | 中断、失效与恢复 | 正式变更发生点 |
|---|---|---|---|
| 初次使用 | 创建→选流程/模板/要求版本→规划或跳过→空白/导入→任务与写作 | 无材料、无规划、导入失败不阻断空白开始；项目切换隔离 | 学生保存项目/导入，AI不代填真实进度 |
| 规范准备 | 上传→解析状态→原件/来源/未知项→纠正新版本→绑定 | 部分/失败/取消保留原件；历史绑定不静默取最新 | 明确绑定；格式应用另走候选 |
| 受控修订 | 真选区→目标/上下文→候选→程序检查→逐项决定→采纳→版本→撤销/恢复 | 无效结构、越界、对象不支持、旧稿、重叠、取消迟到必须阻断并给恢复入口 | 学生明确采纳且再次校验通过的同一事务 |
| 文献到引用 | 查询→核对取得范围/来源→选多篇→提问→受控引用候选→审阅采纳 | 无结果、仅摘要、来源冲突/不可核实不能伪装已读全文；旧稿重新审阅；原交付还禁止未核实来源参与提问，差异见来源台账第9节 | 通过来源和受控引用规则后采纳；不能通过关闭原引用保护“修复”流程；提问例外尚未确认 |
| 任务与进度 | 新增/依赖/日期→关联具体证据→核验/确认→派生进度与事件→计划候选 | 循环依赖/硬截止/无可行解明确解释；换证据、返工保留历史 | 学生确认任务或采纳计划；所有真实任务参与，不只样例ID |
| 导师反馈 | 粘贴保留原文→拆分建议→纠正含义/定位→创建/关联任务→证据→学生处理 | 歧义/定位失败/缺证据待处理；重新整理/证据变化留痕；取消不生成迟到条目 | 学生采纳任务、确认处理；从不生成导师认可 |
| 只评审 | 范围/固定输入→运行→问题/评分依据/未检查项→只读定位→报告导出 | 超时、部分完成、取消可继续；旧报告对应旧稿；下载失败可重试 | 只新增运行和报告；请求修订需要独立决定 |
| 多助手 | 综合↔专业→独立会话/草稿/上下文→引用同一正文→候选 | 切项目/切助手/取消不丢草稿、串用输入或越权 | 消息不是正式正文；每次候选独立关联来源和版本 |
| 四库运行 | API→模型→提示词→智能体→变量/能力/关联校验→运行快照 | 停用/无效引用/缺变量/认证/限流/超时/不兼容明确诊断；重试保留原尝试 | 配置保存产生新版本，不追改旧运行 |
| 保存与恢复 | 本地保存→刷新恢复；下载备份→文件校验→恢复副本 | 存储失败保留内存；损坏备份拒绝；中断任务以合法取消/失败状态恢复 | 通过校验后写入；手动备份不能代替刷新恢复 |

## 6. 模块数据和状态所有权

下表是完整Mock需要的职责契约，名称可沿用现有代码；“需要”不代表已经落地。

| 对象族 | 所有者与关键关联 | 必须保存的事实 | 写入约束 |
|---|---|---|---|
| Project / WorkflowVersion | 项目及阶段模块；绑定流程、模板、要求版本 | 稳定ID、阶段、截止、个人规划、已有产物和归档状态 | 绑定指定快照，阶段确认可追溯 |
| Document / DocumentVersion | 唯一编辑器适配及文稿状态 | 文档schema/结构、正文版本、保存状态、章节稳定标识、保护对象 | 手动编辑与AI应用分开；恢复追加版本 |
| RevisionCandidate / Decision | 修订模块，绑定文稿/选区/助手/资料 | 原片段、差异、目标、依据、保护结果、基础/结果版本、逐片段决定 | 多候选可追溯；新候选不能抹去旧决定详情 |
| Conversation / Run | AI会话与执行层，按项目和助手关联 | 消息、输入草稿、调用上下文、取消令牌、运行配置快照 | 切换不串会话；旧响应不得覆盖新上下文或写正文 |
| Task / EvidenceLink / PlanVersion | 计划模块；引用正文/资料/反馈版本 | 日期、依赖、验收、证据状态、学生确认与返工、计划候选及历史 | 不移动硬截止假造可行解；确认需有依据 |
| Feedback / FeedbackItem | 反馈模块；引用任务及具体修改证据 | 完整原话、录入来源/时间、理解修正、定位、处理与撤销历史 | 不猜导师姓名/时间；处理不等于认可 |
| Material / Template / RequirementVersion | 资料模块；保留原件、版本和来源位置 | 原始/提取内容、未知/冲突、规则范围/参数/类型、绑定版本 | 上传不改正文；纠正有新版本；历史报告能回溯 |
| Literature / ContextSource | 文献模块，与资料/会话/引用候选共享 | 题录/摘要/全文取得范围、核验状态、实际来源 | 没有取得的内容不得作为已读依据；未核实来源的提问限制保留原交付要求，差异单列，不静默放宽 |
| ReviewRun / ReviewReport / RubricVersion | 评审模块；固定文稿/模板/要求/四库配置 | 输入快照、范围、量表、问题/位置/依据/分数/未检查项 | 不写正文或计划；历史报告不随新稿变化 |
| Agent / Prompt / API / ModelVersion | 四库管理；关系双向可查 | 字段约束、引用具体版本、启停、来源/核验时间、运行快照 | 没有真实密钥明文；停用/不兼容不静默换模型 |
| Event / Notification | 主动辅助，关联实际业务对象与项目 | 事件身份、依据、时间、状态、抑制/合并/处理记录 | 冷却按事件/对象处理；状态不冒充采纳结果 |
| Job / Attempt | 统一执行层，覆盖解析/生成/检索/评审/导出 | 请求范围、配置版本、状态、诊断、重试尝试和输出摘要 | 取消令牌阻止迟到；只记必要摘要 |
| Backup | 备份/恢复层，收集项目关联数据 | schema、范围、版本、历史、原件、关联关系与校验 | 全部检查完成后才恢复；未知/损坏拒绝，原项目不变 |

### 服务接口最小语义

依据交付要求 D03/D04/D05，界面与确定性规则、编辑器、模拟服务应分离。服务请求至少有项目ID、对象/基础版本、请求ID、作用范围和取消身份；结果至少区分成功、失败、取消、过期、冲突及部分结果，并携带可解释原因和保留下来的数据。

| 接口族 | 业务行为 | 不得由展示层偷偷代替的部分 |
|---|---|---|
| 项目/文稿仓库 | 读取、保存、指定版本、刷新恢复、归档恢复 | 持久化/失败语义、项目隔离、schema及版本核验 |
| 编辑器适配 | 结构上下文、稳定定位、保护检查、受控事务、历史恢复 | 不能把模型字符串直接塞进整个文稿；复杂对象先拒绝/锁定 |
| AI与检索 | 固定上下文、生成候选或信息、取消/重试、多任务 | 模拟回复必须从服务契约产生，不能在Vue内散落固定“成功” |
| 解析与规则 | 原件保存、解析诊断、版本纠正、适用要求检查 | 来源/未知/冲突与确定性规则不能只靠提示词 |
| 计划与反馈 | 任务约束、证据确认、拆解候选、处理/撤销 | 修改与决定一一对应，不能跨模块复制不关联样例 |
| 评审 | 输入冻结、报告状态、只读定位与导出 | 分数有范围和依据，不拿固定报告冒充任意文档评审 |
| 配置与任务 | 版本引用校验、执行快照、统一Job/Attempt诊断 | 不因更改配置追改历史，不把重试覆盖成同一次运行 |
| 事件与导出 | 业务事件消费、通知规则、下载准备、备份校验恢复 | 下载失败/存储失败、事件幂等和损坏拒绝须可验证 |

## 7. 状态和恢复的统一要求

| 对象 | 应设计的状态 | 允许的后续动作 |
|---|---|---|
| 候选 | 生成中、待审阅、校验失败、已采纳、已拒绝、已取消、已过期 | 生成可取消；失败/过期可重新请求；逐片段接受/拒绝；采纳可安全撤销或比较历史 |
| 任务/证据 | 待开始、进行中、待核验、学生已确认；证据缺失/过期/冲突/解除关联 | 补证据/替换/复核、返工、查看原记录；不直接跳导师认可 |
| 资料解析 | 等待、处理中、成功、部分成功、失败；原件不可用/已移除 | 取消/重试/查看诊断/手动纠正/新版本；保留原件和历史 |
| 要求 | 可判定符合/不符合、语义建议、未检查、未知、冲突、来源缺失/暂不执行 | 查看来源、补来源、纠正参数、绑定版本、明确人工判断；未知或无来源不染成通过 |
| 会话/运行 | 等待、执行、完成、部分失败、失败、取消、旧输入失效 | 停止、重试、看输入/配置快照、保留消息与草稿 |
| 保存与下载 | 空、未保存、保存中、成功、失败；格式不支持/存储满 | 重试/下载替代格式/备份；失败不清空当前内容 |
| 通知 | 未读、已读、延后、忽略/关闭及抑制原因 | 解释依据、跳对象、恢复、补充线下进展；不同于处理对象完成 |

空白、加载、失败、部分、取消、过期、冲突和未知由上述对象语义决定；某行不适用需说明原因。当前没有相应代码不是“不适用”。

## 8. 文档与验收的使用规则

- 每个 `Fxx.nn` 是稳定功能切片；原 F01—F20 和产品 AC 编号保留。模块文件逐项给出可执行验收，后续实现先引用编号再修改代码。
- 当前排查结果仅见[实现审计](design-implementation-audit.md)及各模块矩阵；“本地具备”不等于完整Mock M项或正式产品AC全部通过。
- 缺口不得靠减少功能描述、隐藏按钮或写“后续真实后端”销项；确属未确认设计提议则单独标记，不擅自追加为硬性要求。
- 单元测试、浏览器测试、视觉核对、当前构建、历史构建分别记录。新改动不能借用旧构建测试结果宣布通过。
