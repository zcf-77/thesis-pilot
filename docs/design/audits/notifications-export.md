## F08 功能设计

| 功能编号 | 入口、输入和操作 | 输出、状态、恢复与跨页关联 | 验收方式 |
|---|---|---|---|
| F08.01 事件触发 | 任务延期、缺少可观察进展、学生确认章节/阶段；今日/写作/计划接收提醒 | 从真实本地业务事件生成带项目、对象、版本、时间的建议；测试入口可模拟相同事件。不能将未观察编辑推断为没有工作；无法获取证据则说明未知 | 新建任务并改变期限/完成状态，不使用“预览事件”按钮，核对相应建议及依据；普通输入不反复提醒 |
| F08.02 原因和依据 | 今日提醒、收件箱打开建议详情 | 展示触发原因、来源对象、时间、已知事实和不确定性；跳转具体任务/章节/反馈，不把提醒送达当采纳 | 从提醒回到同项目、同对象，检查过期依据可解释且未自动完成任务 |
| F08.03 去重合并冷却 | 同对象同事件重复触发、不同对象同类事件触发 | 同事件幂等，重复事件可合并；配置冷却期后再次判断，不能把不同对象的提醒错误吞并；取消/关闭后不补发迟到结果 | 同事件重复一次、不同任务各一次，检查ID/次数/对象与冷却依据 |
| F08.04 开关与静默 | 账户接受主动建议开关、跨午夜静默；配置延期阈值/冷却 | 使用同一规则，已存建议保留；静默抑制新通知，结束后的策略可解释；无效时间/阈值不能写入 | 关闭/开启、跨午夜/相同时段、低于阈值分别触发，检查新增数和原建议不丢失 |
| F08.05 延后忽略与恢复 | 收件箱已读、选择延后时间、忽略、查看延后项、放回待留意 | 立即改变建议状态并展示延后截止，不影响业务任务；普通可逆操作直接执行，状态变更有记录；空分类可切换恢复 | 每个动作后切分类再返回，核对状态、延后截止、操作记录和关联对象 |
| F08.06 线下进展 | 建议详情补充线下工作文字，保存/取消 | 保留学生原话和时间、关联原建议；不能由线下说明自动确认任务或宣称导师认可；空内容不写入 | 输入/取消/空值/再次补充另一条路径可用，任务确认状态保持不变 |
| F08.07 介入层级 | 不打扰标记、任务角标、单条提醒、收件箱及重大节点 | 按下表保留 L0–L4 的权限边界；任何建议不得使用L4，L3只在今日/计划且可延后忽略 | 查看延期/阶段事件，确认只按配置介入，存在明确关闭/延后路径；缺事件证据时不造紧迫等级 |
| F08.08 今日聚合 | 今日“等你决定”与下一步入口 | 聚合待审阅修订、待采纳计划、待澄清反馈及通知；去往对应候选/批次；无待办有空态；结果失效时可重新生成或复核 | 各模块分别产生待决定事项，回今日检查数量、类型、跳转及处理后减少 |

原交付 `DESIGN-SPEC` §2的介入层级约束：

| 层级 | 允许行为 |
|---|---|
| L0 | 仅记录，不打扰 |
| L1 | 角标；写作稿纸最多采用此层级 |
| L2 | 进入收件箱，不主动弹出 |
| L3 | 仅今日/计划出现重大节点提醒，可延后、忽略 |
| L4 | 仅版本冲突、会话失效、可能丢稿等阻断；任何建议都不使用 |

## F20 功能设计

| 功能编号 | 入口、输入和操作 | 输出、状态、恢复与跨页关联 | 验收方式 |
|---|---|---|---|
| F20.01 论文文件 | 导出页选择当前正文及已支持格式 | 真正生成 HTML/文本；文件名/MIME/内容版本一致，空文档有明确结果；不将文本伪装为DOCX | 实际下载后读取并比对正文、表格/转义和版本 |
| F20.02 评审报告 | 导出页及评审历史选择报告 | 导出所选报告的固定输入、问题、分数依据、未知项和旧稿说明；未评审则给发起入口 | 修改正文后导出旧报告，内容仍对应旧输入；无报告可进入评审 |
| F20.03 修改说明 | 导出实际变更/修订决定 | 来自真实版本和采纳记录，区分手工编辑/AI采纳/撤销；可追踪片段及基础/结果版本；无记录不造修改 | 采纳部分片段并撤销，核对导出记录对应决定与版本，而非固定文案 |
| F20.04 项目备份 | 下载当前项目文稿/历史、模块和关联数据 | 带备份schema、导出时间、对象ID及版本；范围明确，原资料/关联证据可续用；无模块仍是合法空项目 | 遍历已创建模块，下载JSON并检查关联完整性及用户内容未遗漏 |
| F20.05 校验和恢复 | 选择备份→读取/校验→预览→恢复/取消 | 损坏JSON、未知schema、非法对象拒绝，原项目不变；合法恢复为明确副本；不跨项目混用，已取消动作不补执行 | 合法/损坏/未知模块/非法状态、过大文件分别恢复，检查原项目及恢复副本 |
| F20.06 中断执行恢复 | 含排队/解析/生成中任务的备份 | 不恢复已经失效的定时器；使用各模块合法取消/失败状态，保留原件和历史，可明确重新执行 | 备份运行中的任务/资料，恢复后等待原完成时间仍不成功，再人工重试 |
| F20.07 失败与可继续路径 | 论文/报告/备份生成失败或已知不支持转换 | 保留文稿/报告、给出具体错误与重试/真实替代格式；只有触发浏览器下载时不能声称已经写入用户磁盘 | 模拟Blob/下载准备失败，核对状态和重试；DOCX/PDF不可用时下载真实HTML/TXT |
| F20.08 自动保存、刷新和重置 | 本地编辑后刷新、存储异常、重置样例 | 在完整Mock范围内要求刷新恢复；存储失败保留内存及重试/备份；重置不无提示覆盖用户数据 | 刷新后正文/任务/会话一致；模拟存储失败；重置前有具体影响与可恢复路径 |

F20.08 同时属于 F04 和交付要求第3.3/5节，是已有明确要求。当前选择内存预览并披露“刷新清空”，只能说明限制，不能据此删除刷新恢复的验收项。
