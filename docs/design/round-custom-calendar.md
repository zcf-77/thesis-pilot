# 自定义日期与时间控件

日期：2026-11-14。用户要求：“永远不要用基础组价啊 Select框等等都不要用基础的 太丑了！”本轮在现有页面中统一替换浏览器默认控件，不新增业务页面。

## 功能与交互设计

关联 F02 项目截止、F03 阶段日期、F07 计划日期、F08 延后截止、F01 静默时间及组件展台。所有入口复用 `TpDatePicker`，`type` 区分日期、时间、日期时间；业务存储仍使用 ISO 字符串，已有日期判断不随外观更换。

| 功能 | 入口/输入 | 结果及状态 | 验收 |
|---|---|---|---|
| 日期选择 | 标签关联的文字输入、日历按钮 | 自绘月份头、星期、日期网格、前后月、今天、清空；选日后写入 YYYY-MM-DD | 闰年、月界、年界准确；非本月日期可选，禁用/上下界不可选 |
| 时间选择 | ISO 时间直接输入、时钟按钮 | 自绘小时/分钟列表，应用后写入 HH:mm | 不出现原生 select/time；方向键移动和 Enter 选择；取消不修改业务值 |
| 日期时间 | 日期网格及小时/分钟 | 应用后写入 YYYY-MM-DDTHH:mm | 延后截止语义不变；最早/最晚限制检查 |
| 手动修改 | 直接输入 ISO，保留 label/id/aria | 合法值更新业务，非法草稿留在输入框并说明“尚未更新”；不悄悄恢复旧文字 | 无效日期不自动滚到下月；错误保留且可纠正；setCustomValidity 参与表单校验 |
| 键盘与焦点 | Alt+下打开，日期方向键/首尾/PageUp/PageDown，Esc 关闭 | 关闭返回触发按钮；Tab 顺序继续；点击外部收起 | 嵌套模态里 Esc 只关闭选择面板；disabled 不可打开 |
| 统一视觉 | 当前 ThemeScope 和语义令牌 | 自绘输入、图标、浮层、选中/今天/禁用/错误样式 | 四主题继承；390px 视口不溢出；父容器滚动不裁切浮层 |

组件使用原地 DOM 的 Popover 顶层渲染，保留主题继承与模态焦点查询关系；不依赖操作系统日期/时间弹层，不新增依赖。原生文本输入仅作为文字输入和表单语义基础，外观全部由设计令牌控制。

## 同轮动效补充

用户进一步明确要求全局具有实际动效。日期/时间面板现将“逻辑打开”和“离场仍在画面中”分离：进入读取当前主题的进入变换、滤镜、时长和曲线；关闭立即设为 inert、移出无障碍交互范围，再完成真实淡出后关闭 Popover。每次开关增加独立序号并取消旧动画，快速重开不能被旧离场回调隐藏；卸载清理动画。月份改变在原网格节点上播放轻淡入，保留文字草稿和键盘定位，不重建整个输入。

完整动效复用 `--tp-dur-base`、`--tp-dur-fast`、`--tp-ease-enter/exit` 和 `--tp-enter-transform/filter`；减弱模式及系统偏好使用100ms纯透明度，不使用位移、缩放或滤镜。选择即提交/应用时间规则与 ISO 业务状态不变。动效改动后定向格式化、lint、类型检查及原6项单元回归通过；浏览器的实际动画与快速重开验证由主任务执行。

## 集成发现的焦点问题

主任务浏览器检查发现点击新日期未改变输入、点击小时时面板消失。独立只读事件探针复现：`2026-11-14` 到 `2026-11-20` 的焦点转移中，focusout 的 relatedTarget 已正确指向新日期，但 activeElement 暂时为 BODY；原 nextTick 检查误以为离开控件，提前将面板 inert，后续 click 因而没有送达。

修正为优先识别 relatedTarget 位于控件内部的转移；只有真正外部/未知目标才在下一宏任务复核，focusin 取消待定检查，并用开关序号拒绝旧检查关闭重新打开的面板。日期选择、时间应用规则和测试原断言均保留。定向格式化及 lint 通过；修正后浏览器结果由主任务重建复测登记，未将旧构建的探针写成修正已通过。
