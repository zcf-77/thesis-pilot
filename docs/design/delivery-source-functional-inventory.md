## 7. 状态、数据与权限是功能设计的一部分

### 7.1 五种业务语义，不是五种配色

| 语义 | 应用于何种事实 | 必须禁止的混淆 |
|---|---|---|
| 墨 | 学生正文、导师原话、已采纳内容、有效历史 | 不能把未采纳AI产出写成正式事实 |
| 铅笔 | 修订/计划/反馈拆解/引用/语义建议候选 | 不能把“接受片段”当成已经改正文；必须再经采纳和程序校验 |
| 印章 | 学生采纳、确认完成、标记处理及决定记录 | 不用于系统成功、AI结论、导师认可 |
| 留白 | 未知、未检查、缺来源、未识别、取消 | 不等于没问题、符合或0分 |
| 旧稿 | 基于过期正文的候选/报告、被替换证据 | 仍有效的历史事实不能仅因时间旧而视为失效 |

来源：S1原版 §2.1—2.2（L33—61），S4 L19—39。审计应检查行为和数据，而不只检查颜色是否对应。

### 7.2 候选七状态与决定顺序

| 状态 | 用户应能知道和做到 | 对正文的效应 |
|---|---|---|
| generating 生成中 | 知道正在起草，可取消；迟到响应不恢复已取消候选 | 无 |
| pending 待审阅 | 看差异、理由、来源、基础版本和校验；逐片段接受/拒绝，最终采纳 | 最终采纳前无 |
| invalid 校验失败 | 看保护/越界/结构等原因，不能采纳，可纠正后重生成 | 无 |
| adopted 已采纳 | 显示学生决定与结果版本，可撤销或历史比较 | 经校验形成新正文版本 |
| rejected 已拒绝 | 保留拒绝事实，正文原样 | 无 |
| cancelled 已取消 | 保留取消记录，迟到结果丢弃 | 无 |
| expired 已过期 | 明示基础/当前版本，重新生成或重新审阅，不覆盖新稿 | 无 |

来源：S8 `CandidateStatus` / `candidateStatus`，S4 L42—69、L172。每片段另有pending/accepted/rejected；最终组合需再检查number/citation/formula/lock/range/version/overlap，检查结论为pass/fail/unsupported。`unsupported`不是通过。

### 7.3 全界面的九种状态与恢复契约

空：解释内容并提供第一步；加载：保留布局并给过程状态；成功：说明哪份对象/哪个版本改变；部分完成：明确成功、失败、未执行子项；失败：说明原数据安全及重试/替代路线，不能自动消失；取消：结果丢弃留痕；过期：展示基础/当前版本并引导重生成；冲突：展示冲突双方并由本人选择；未知：解释无法判断的原因，不给默认结论。来源S1原版 §11（L421—437）。

对应业务枚举还包括：任务todo/doing/verify/confirmed；执行子任务waiting/running/done/failed/cancelled；解析waiting/processing/parsed/partial/failed；后台任务queued/running/done/partial/failed/cancelled；要求六结论。组件能够切换这些样例状态，不等于当前业务有完整触发、恢复和跨页传播。

### 7.4 原交付已明确的数据责任

| 对象 | 原稿明确携带的信息 | 跨模块约束 |
|---|---|---|
| StageView | 阶段ID、名称、已过/当前/后续、日期、说明 | 当前阶段与流程版本应一致；查看不等于推进 |
| TaskView / EvidenceView | 验收、期限/硬截止、章节、依赖、产物类型/版本/过期、确认时间 | 正文/资料更新能让已关联证据需要复核 |
| CandidateView / HunkView | 助手、目标、范围、基础/当前/结果版本、片段差异、理由、决定、保护检查、依据 | 编辑器与副驾消费同一候选；决定权不得分散到自动动作 |
| RunStepView | 子任务ID、助手、标题、状态、详情 | 一项失败不能抹掉其余结果；要体现部分失败 |
| SuggestionView | 事件/时间、级别、关联对象、依据、不确定性、未读/延后/忽略和延后期限 | 提醒到达不是任务完成，也不是采纳 |
| FeedbackView | 原文、来源/时间、文稿版本、拆解/定位/标记、学生纠正与处理 | 原文独立保存；理解与处理可变，导师认可不存在 |
| MaterialView | 原件名称/类型/大小、类别、版本、解析进度/识别统计/诊断、重复版本 | 解析失败也保留原件；新版本不覆盖历史 |
| RequirementView / LiteratureView | 要求种类/参数/来源/版本/结论；文献题录/取得范围/核验/收藏 | 来源和取得范围约束可用上下文，不能只存一个“成功”布尔值 |
| ScoreDimView / IssueView | 可为空的分数、满分/解释、严重程度、问题位置/依据/建议 | 未检查和不可评分单列；报告绑定输入版本 |
| JobView / ConfigNodeView | 任务类别/范围/快照/进度/次数/诊断；库名/版本/启用停用无效原因 | 已有运行结果不被当前配置变动改写 |
| VersionView / PlanBarView | 版本成因/时间/字数/当前标记；原/新任务位置与硬截止 | 恢复追加新版本；调整保留对比及决定 |

来源S8；其文件首注明确为“设计阶段子集”，正式ID/版本关联与服务契约仍须完善，不能据此宣称数据库或后端已经实现。

## 10. 文档补全与实现核对的使用方式

1. 把DS-01—46对应行为纳入现有F01—F20模块说明和验收，而不是只添加组件名或色值。原设计没有给出细则的部分，保留现有产品需求，不反向缩减。
2. 审计每项分别记录“设计来源明确程度、页面入口、实际调用链/数据源、成功与恢复、跨页关联、实现状态、验收证据”。引用组件存在只能证明展示能力；不能证明页面已接入。
3. 优先避免遗漏：全局航线与保存信息、四个不同口径的进度（阶段位置、阶段已用时间比例、任务确认比例、字数目标）、目录稳定定位与确认、综合/专业/多助手、可收起调宽副驾、同屏双处差异、选区气泡、今日待决定聚合、章节/AI指令入口、只读评审定位、常驻任务及各类恢复。
4. 本轮记录是来源分析及功能设计提取，不包含应用改动、发布、提交或全套产品验收结果；暂停中的写作页修改与上一轮构建产物必须分别审计。

### 11.2 配置台不显示副驾的静态核对

当前源码结构符合这一布局约束：`apps/web/src/lab/pages/PageScreens.vue:62` 将配置空间映射到 `ScreenSettings`，第72行按当前空间选择组件，第135行只渲染当前组件并使用KeepAlive保留其他页面；外壳本身没有另行挂载副驾。`apps/web/src/lab/screens/ScreenSettings.vue:354—390` 为独立配置页及管理页签/列表结构，文件未引入或渲染写作副驾/会话输入组件。因而进入配置台不会同时显示写作页副驾；KeepAlive中的写作页缓存不等于配置页可见副驾。

该结论只确认“独立空间、不显示副驾”的当前源码结构，不证明配置台全部功能已完成，也不代替当前构建及浏览器验收。四库/流程/诊断的功能缺口仍按R、W分册分别保留。
