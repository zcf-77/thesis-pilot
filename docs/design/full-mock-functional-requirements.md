# 毕设智途：全套 Mock 前端功能需求

版本：2026-11-11；2026-11-14 补充文字录入及功能设计前置、统一视觉要求。与《全套 Mock 前端交付与验收要求》一起使用。

本文是交给设计与前端智能体的产品需求。必须先逐项完成功能流程与状态设计，再基于现有 `apps/web` 的 Vue 展台继续实现；视觉、布局、排版、导航与组件遵循 [DESIGN-SPEC](../../apps/web/docs/design/DESIGN-SPEC.md)，保持全局统一。旧原型仅供历史追溯，不作为当前实现依据。

## 1. 产品定位

中文名称：毕设智途。英文名称：ThesisPilot。

帮助学生完成从开题到答辩结束的毕业论文过程：理解每个阶段需要做什么、管理任务和产物、撰写论文、查询文献、处理导师意见、检查格式、获取评审问题清单。

产品基调是：**AI 主动判断并提供帮助，重要节点介入，学生最终决定。** 学生不必一直主动提问，但系统也不能持续打断写作。任何改变正式论文或正式任务计划的 AI 建议，都必须先经学生采纳。

本轮交付是完整、可操作、可持续接入后端的 Mock 前端。真实 AI、数据库、文档解析和外部检索可用模拟服务替代；前端交互、状态变化、编辑、采纳和恢复必须真实发生，不能仅制作静态页面或跳转演示。

## 2. 参与者与范围

### 2.1 学生使用范围

- 创建和管理自己的论文项目。
- 查看阶段要求、个人规划、任务与进度。
- 在系统内编辑论文，与综合助手或专业助手沟通。
- 管理论文模板、规范、文献、参考资料和导师反馈。
- 审阅 AI 修改建议、接受或拒绝、查看历史及恢复版本。
- 发起整篇或指定章节的独立评审，获得问题清单、参考评分和报告。

### 2.2 管理配置范围

- 管理流程、模板、要求、资料及其版本。
- 管理智能体库、提示词库、AI API 接口库、模型库及关联配置。
- 查看基础用户、会话、通知、文件、字典、后台任务和运行诊断。

学生功能与管理配置都需要可操作入口。本轮不建设真实身份认证或角色权限体系，演示身份与配置入口不应被描述为已完成安全隔离。

### 2.3 明确不包含

- 院长审批；流程直接从开题开始。
- 学校租户、学院/专业层级配置、三校切换和角色权限系统。
- 独立教师账号、教师审批工作台、多人协同编辑及跨设备同步。
- 资料上传后的核对发布流程、规则更新影响评估和自动迁移。
- 整篇论文代写、虚构实验或参考文献、查重或 AI 检测规避。
- 真实模型调用、真实密钥管理服务、正式部署及比赛报名提交。

上述功能不作为本轮交付范围；不要为它们增加无法使用的占位入口。

## 3. 功能模块

### F01 基础用户与会话

- 展示演示用户资料，支持修改与当前任务有关的基本偏好。
- 模拟进入、退出和会话失效；会话失效时说明当前编辑的保存状态，不能清空文稿。
- 通知偏好包括是否接受主动建议、静默时段和已延后建议的查看方式。
- 管理端可查看演示用户和会话状态；账号验证、密码找回及权限分配不在本轮范围。

### F02 论文项目与首次设置

- 新建、编辑、切换、归档和恢复论文项目；切换项目不能混用正文、资料、会话或任务。
- 保存题目、项目状态、当前阶段、重要截止时间，以及绑定的流程、模板和要求版本。
- 第一次设置时允许填写个人规划、已有进度、已完成产物；规划可以暂不填写。
- 未填写规划时，根据已知截止时间、任务与产物提供提醒，不推测学生的实际效率。
- 导入既有论文和从空文档开始都应有可继续的使用流程；解析能力的模拟边界见第 6 节。
- 项目详情能访问其论文、阶段、任务、资料、反馈、候选建议、版本和报告。

### F03 毕设流程与阶段配置

- 覆盖开题、中期检查、论文撰写、论文提交、答辩及结束状态；具体阶段名称和顺序可配置，不声称这是某所学校的真实流程。
- 阶段配置包含说明、所需产物、完成条件、截止时间及前后置关系。
- 管理配置支持新增、编辑、停用和版本查看，项目绑定明确版本。
- 学生能知道当前阶段的要求、尚缺内容和下一步工作。
- 阶段或任务完成由学生确认；系统据此更新派生进度、依赖状态和提醒。

### F04 论文编辑与文档结构

- 使用 Tiptap 作为本轮编辑内核，真实支持输入、选择、光标定位、标题、段落、列表、基础表格、撤销和重做。
- 支持章节识别与定位、字数和保存状态、选区与当前章节上下文。
- 允许对具体文字或对象设置保护/锁定；学生直接编辑与 AI 候选应用的保护策略须明确区分。
- 论文数字、引用、公式、锁定内容及选区边界是 AI 修订的保护对象。
- 对当前不能安全解析或修改的对象，保留原件、锁定或明确拒绝；不能丢失对象后报成功。
- 图片、公式、图注、目录、页码、参考文献等对象需要有功能和状态设计；可编辑能力按实际扩展验证，不把可视样例冒充完整实现。
- 文档状态在模式切换、打开模块、查询文献、查看评审或配置时保持一致；不重复建立互相覆盖的正文实例。
- 记录文档结构版本与保存失败。正文保存不是 AI 修改采纳，两者应独立处理。

### F05 AI 修订、审阅与版本历史

- 修订请求明确作用范围、目标、选用资料、保护项及基础正文版本。
- 生成候选只产生建议，不写入正式正文；显示实际差异、修改理由和相关依据。
- 支持按候选片段接受或拒绝。批量或部分接受时，必须校验最终组合结果。
- 数字、引用、公式、锁定项、越界范围、重叠补丁由程序检查，不能仅依赖模拟 AI 的声明。
- 学生明确采纳后才应用修改，并保存决策与新正文版本。
- 正文变动后，基于旧版本的候选不能直接覆盖新稿；提供重新生成或重新审阅的处理路径。
- 支持撤销、查看版本、对比版本和可追溯恢复；恢复不删除原有历史。
- 取消后的迟到结果、重复响应和重复点击不能重复应用或恢复已取消候选。

### F06 综合 AI 与专业 AI

- 提供综合模式，以及将能力拆分为专业助手的模式；用户可在同一项目中切换。
- 支持单个助手会话及多个专业助手同时打开，保留各自会话、输入草稿和论文上下文。具体呈现方式与同时显示数量由设计决定。
- 专业助手至少包括：文献查询、论文内容辅助、格式规范、进度管控、论文评审。
- 综合助手能协调专业任务；多个助手共享项目事实，不因角色切换获得更大的写入权限。
- 明确本次使用的项目、论文版本、章节/选区及资料范围；用户能调整上下文。
- 支持提问、查看回复、取消、重试、历史会话和执行状态；不能切换项目后把结果写到另一个项目。
- 一次复杂请求可能产生多个任务；应能区分等待、执行、完成、部分失败与取消，不用模糊成功提示掩盖失败。
- 专业查询可以只返回信息或问题，不必自动生成修改；需要修改时进入 F05。

### F07 任务、个人计划与进度

- 任务包括目标、验收条件、期限、前后置依赖、关联章节和交付物具体版本。
- 支持创建、编辑、排序或调整依赖、状态变更和返工记录；常规可逆修改无需重复确认。
- 区分待开始、进行中、待核验、学生已确认完成；单凭字数、文件存在或 AI 判断不能直接完成确认。
- 学生确认后自动更新派生进度；完成状态能追溯到实际证据和确认记录。
- 证据被替换或对应正文版本变化时，保留旧关联，并提示需要复核的状态。
- 支持有规划与无规划两种使用路径。
- AI 给出调整候选，说明触发原因、受影响任务及调整前后差异；学生采纳前正式计划不变。
- 检查循环依赖、前后置日期冲突、硬截止及无可行方案；不能偷偷移动硬截止制造可行结果。
- 进度与质量分开表达，不把任务完成比例展示为论文质量评分。

### F08 主动辅助与通知

- 支持明显延期、持续缺少可观察进展、完成重要章节、完成阶段等事件。
- 每条建议可追溯触发事件、时间、相关任务/章节、已知依据及不确定性。
- “未观察到编辑”不能直接判为“学生没有工作”，允许学生补充线下进展。
- 按事件去重、合并和冷却，尊重用户静默与关闭设置；常规输入不触发反复提醒。
- 支持查看、延后、忽略、关闭，以及之后重新访问延后的建议。
- 根据重要性和紧迫性区分待处理事项，原因可解释；不以颜色或虚构紧迫分数代替依据。
- 通知支持未读/已读、关联对象跳转和处理记录。提醒送达与建议被采纳是不同状态。
- 模拟事件可从单独的测试场景入口触发，不混进正常学生业务操作。

### F09 导师反馈

- 导师反馈仅通过粘贴文字录入（2026-11-14 用户确认），保留完整原文并记录文字录入来源及录入时间；未知的导师反馈时间、姓名及关联论文版本不自动推断。
- 录入入口只提供一个多行文本框与保存/取消动作，不增加文件上传、截图识别、资料库选择或额外必填元信息。
- 模拟 AI 拆解为任务或检查项，学生可以纠正含义、章节定位与任务内容。
- 对歧义、无法定位和缺少材料的意见显式标记，不编造确定解释。
- 关联具体修改、正文版本和处理证据，保留处理历史。
- “学生已处理”与“导师已认可”不同；本轮没有教师审批功能，不产生导师认可状态。

### F10 文件、资料与知识库

- 上传、查看、整理和关联资料；保留原件、文件类型、来源、版本、所属项目和处理状态。
- 支持模板、规范、参考材料、文献附件及导师反馈文件等业务分类；分类配置可维护。
- 上传后直接进入解析和版本保存，支持等待、处理中、成功、部分成功和失败，不增加核对发布步骤。
- 同一资料更新产生新版本，不覆盖旧原件；重复上传与重复处理可追溯。
- 可查看提取结果、来源定位、诊断、未识别内容，并纠正可编辑结果形成新版本。
- 知识库条目与来源文件及版本绑定；检索结果必须回到来源，不建立无法解释的知识结论。
- 文件移除、项目解除关联和历史版本保留的区别应明确，不能使历史报告失去依据。

### F11 模板导入、解析与版本

- 管理模板名称、用途、原始文件、来源、版本、解析状态及支持范围。
- 展示解析得到的文档结构与格式项，包括标题层级、字体字号、段落、页边距、页眉页脚等适用信息；没有识别的项目标为未知。
- 支持查看和纠正解析项，修正形成新版本；冲突和无法识别项目必须可见。
- 项目绑定具体模板版本；选择模板不等于自动修改既有正文。
- 对已有论文应用格式变更时，先生成可审阅候选，学生采纳后生效。
- 模板“解析成功”与“所有格式都能编辑或导出”不同，应分别记录。
- 本轮不做模板更新对已有项目的影响评估或全量迁移。

### F12 论文要求抽取与管理

- 从上传规范与模板中抽取要求；模拟结果也必须有原文、位置、来源文件与版本。
- 要求包含适用范围、类型、参数、严格程度、是否可自动判定及不确定性。
- 覆盖章节结构、字数、格式、引用样式、引用数量与年份范围等规范可能包含的项目；这些是规则类型，不预设统一数值。
- 支持查看、筛选、编辑、停用及版本记录，原文和修正结果分别保留。
- 能确定执行的硬规则由代码检查，语义要求输出带依据的判断；缺标准或标准矛盾时说明不能判定。
- 所有专业助手使用同一组适用要求；提示词或资料中的指令不得绕过硬规则。
- 项目及评审任务绑定具体要求版本；上传资料不触发正文修改。

### F13 文献查询与引用辅助

- 支持关键词查询、结果筛选、详情、来源查看、保存到项目资料及后续引用建议。
- 区分已取得的题录、摘要和全文，标记来源、获取范围及核验状态。
- 学生可选择一篇或多篇资料与助手沟通；回复依据不超出实际取得内容。
- 引文与参考文献变更先形成候选，不直接插入正式正文。
- 提供无结果、来源不可用、只有摘要、全文不可访问、题录冲突和无法核实等状态。
- Mock 查询明确使用样例来源。采用自制资料或经核验的公开资料，不制造看似真实的作者、DOI、期刊、页码或研究结论。

### F14 论文评审与仅评审

- 学生能不经过修改流程，直接选择整篇或指定章节进行评审。
- 评审输入固定正文、模板、要求、评分量表及配置版本；执行期间的新编辑不应偷偷成为同一次报告的输入。
- 输出问题清单、严重程度、章节或片段位置、依据、修改建议、分项参考评分、未检查项和不能判定项。
- 量表与评分依据可查看，参考评分不等于教师成绩或学校通过结论。
- 从问题定位相关内容；学生可自行调整，也可另行请求修订候选。
- 仅评审不得改变正文、正式计划、任务完成或导师认可状态。
- 保存评审历史、查看报告对应版本；正文已更新时明确报告基于旧稿。
- 支持导出报告，失败有可继续路径。Mock 报告与模拟分数明确标识，不将固定报告套用于任意上传文档并宣称真实评审。

### F15 智能体库

- 管理综合与五类专业智能体，支持新增、编辑、停用和版本查看。
- 字段包含名称、职责、适用任务、允许使用的工具、输入/输出结构、提示词版本及模型配置引用。
- 关联配置不存在、停用、不兼容时阻止无效配置或明确解释，不静默替换。
- 提供模拟运行及运行记录，查看实际选用的配置快照。
- 不允许通过管理页面上传任意可执行代码，也不能配置绕过论文与计划保护的权限。

### F16 提示词库

- 管理名称、用途、正文、变量、输出约束、版本和引用关系。
- 支持创建、编辑、复制、停用、版本比较与模拟预览。
- 检查缺少变量、无效变量和不符合输出结构的模拟结果。
- 修改配置不追改历史运行；执行时绑定具体版本。
- 原始论文与检索内容作为数据传入，不能改变工具权限或正式写入范围。

### F17 AI API 接口库

- 管理服务名称、协议、地址、超时、重试/限流配置、密钥引用、启停状态及版本。
- 模拟连通性测试，包含成功、认证失败、超时、限流和返回不兼容等情况，并明确这是模拟结果。
- 本轮使用虚构密钥引用或脱敏占位，不要求输入真实密钥，不向外部地址发送真实请求。
- 不在普通详情、日志、导出或本地存储中保存真实密钥。
- 能查看被哪些模型或任务使用，停用行为有明确提示。

### F18 模型库

- 管理模型名称、服务商模型标识、所属 API、能力、上下文限制、参数及启停状态。
- 费用或能力信息包含来源与核验时间；Mock 中使用明确的示例值或未知值。
- 配置校验包括 API 不存在/停用、模型能力与任务不匹配、参数越界等情况。
- 支持版本查看、引用关系和模拟测试；不静默换用另一模型。
- 模型库、API 库、提示词库、智能体库保持可追溯关联，运行记录固定配置版本。

### F19 系统配置、执行任务与诊断

- 维护业务字典、资料分类、阶段配置和提醒参数等现有模块需要的配置。
- 展示解析、生成、检索、评审、导出等后台任务的排队、执行、完成、失败、取消状态。
- 查看任务输入范围、项目/文档版本、配置版本、输出摘要、诊断与重试记录。
- 支持取消和重试；取消后迟到结果不能恢复任务或改写数据，重复执行不重复产生正式修改。
- 运行记录只包含必要摘要，不能泄漏全文论文或密钥。

### F20 导出、备份与恢复

- 论文导出、评审报告导出、修改说明、项目备份是不同操作，需要分别体现状态与支持格式。
- 实际下载的文件必须可打开且对应当前内容；修改说明来自真实采纳记录。
- 支持包含文稿、历史、任务及关联数据的本地项目备份与恢复；损坏备份不能覆盖当前项目。
- DOCX/PDF 尚无真实转换时，可模拟任务与故障界面，但不能把文本改扩展名或使用无关固定文件宣称导出成功。
- 可提供真实的 JSON/文本/HTML 等已实现格式，清楚写明格式；是否增加 DOCX/PDF 转换由后续接入验证决定，不要求本轮编写完整排版引擎。

## 4. 必须串通的使用流程

| 流程 | 完整结果 |
|---|---|
| 新项目开始 | 创建项目→选择流程和模板版本→填写或跳过个人规划→建立任务→开始论文 |
| 规范与模板 | 上传样例→模拟解析→查看来源及未知项→修正并形成版本→绑定项目 |
| 写作与修订 | 编辑→选择范围→提出目标→生成候选→查看差异→拒绝/采纳→版本变化→撤销/恢复 |
| 文献研究 | 查询样例→查看实际内容范围→关联资料→提问→生成引用候选→学生决定 |
| 进度与计划 | 任务关联产物→学生确认→更新进度→事件提醒→调整候选→采纳或保留原计划 |
| 导师反馈 | 保留原文→拆解建议→学生纠正→关联任务与修改证据→标记学生已处理 |
| 仅评审 | 选择范围和版本→模拟评审→问题定位→查看参考分与未检查项→报告导出；正文和计划不变 |
| 多助手 | 综合与专业模式切换→多个会话独立沟通→保留草稿和选区→同一论文版本产生可审阅候选 |
| 四库管理 | 配置 API→配置模型→配置提示词→关联智能体→模拟运行→查看所用版本→停用/无效关联处理 |
| 异常恢复 | 失败/取消/重试→保留原数据→识别旧结果→继续操作；刷新、备份及恢复后数据一致 |

箭头表示业务依赖，不限定页面数量、导航顺序或交互呈现方式。

## 5. 跨模块数据原则

- 所有业务对象有稳定 ID；项目、正文、模板、规则、资料和配置有明确版本。
- 同一对象在不同功能中的状态一致，不能每个模块各写一份互不关联的样例。
- 正文版本、任务完成、质量评分、学生处理和导师认可各自独立，不互相冒充。
- 建议状态至少区分生成中、待审阅、校验失败、已采纳、已拒绝、已取消、已过期。
- 模拟服务返回结构化结果，展示组件不自行制造“已成功”的业务事实。
- 正式论文与计划的 AI 修改须由学生采纳并经业务校验后写入；保存草稿、生成候选、记录提醒及更新已确认事实的派生进度可以自动执行。失败保留原数据并给出后续处理方式。
- 用户资料和文档内容不得改变系统工具权限；模拟环境也应体现这一边界。

## 6. Mock 与真实前端的分界

| 必须真实执行 | 可以模拟，但必须明确 |
|---|---|
| 路由、模块访问、表单校验、增改停用、对象关联 | 登录认证与外部服务状态 |
| Tiptap 文本编辑、支持的对象操作、选区、撤销重做 | DOCX/PDF 解析、复杂排版和保真转换 |
| 候选差异、采纳/拒绝、范围与版本检查、本地状态变化 | AI 生成的候选内容、回复及语义判断 |
| 任务依赖与日期约束、学生确认、计划采纳 | AI 规划建议和风险解释文本 |
| 会话隔离、取消后结果抑制、事件去重 | 网络延迟、超时、限流和服务错误 |
| 报告查看、问题定位、真实可打开的已支持格式下载 | 评审评分、检索结果和模拟解析结果 |
| 本地状态保存、刷新恢复、备份与损坏备份拒绝 | 正式数据库原子性、跨端并发和服务端授权 |

对复杂保护对象未能实现的部分，必须展示不支持/锁定状态，不能用一条“校验通过”消息替代程序检查。Mock 不等于只做成功状态，也不等于可以伪造产品能力。

## 7. 当前技术基线

- Vue 3 + TypeScript + Vue Router + Pinia。
- Tailwind CSS + daisyUI；视觉外观、组件与交互统一遵循 `apps/web/docs/design/DESIGN-SPEC.md`。
- Tiptap 3.33.1：`@tiptap/vue-3`、`@tiptap/pm`、`@tiptap/starter-kit`、`@tiptap/extension-table`。
- 工程统一由 Vite+ 管理，底层 pnpm；开发、检查、构建和测试都使用 `vp` 入口。
- 当前工具配置目标：vite-plus 1.6.0、pnpm 11.25.0、Node 26.13.0。交付方需完成干净安装和兼容性验证，不把现有环境或配置文件当作已通过的证明。
- 后续真实后端为 FastAPI；本轮不实现后端，用独立 Mock Service 和明确的数据契约承接。
- MuffinOffice 未接入，只是后续可选服务端文档处理候选，本轮不要求依赖它。
- 先完成功能需求设计及逐项覆盖映射，再复用 `apps/web` 的设计令牌、组件与共享布局实现页面，交付可继续开发的 Vue 源码；旧原型不作为实现依据。

Tiptap 基础接口、扩展边界和技术交付要求详见配套《全套 Mock 前端交付与验收要求》。
