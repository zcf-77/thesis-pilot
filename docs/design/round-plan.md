# 计划页面功能设计与本轮自检

日期：2026-11-14。用户输入：继续把剩下的设计稿完全实现出来，每轮按规范执行并自检。

## 需求、范围与实现前验收

本轮覆盖 F07、P-01—P-08；对应 AC-003、AC-009、AC-016。范围为 Vue 计划页面、项目隔离的预览状态、确定性计划规则及测试；不接入正式后端或真实 AI。

| 功能 | 入口→输入/动作→结果 | 状态与恢复 | 验收 |
|---|---|---|---|
| 任务管理 | 新增任务/详情编辑→目标、验收、起止日期、章节、依赖→保存；列表调整顺序 | 空白校验、日期冲突、循环、硬截止拒绝；保留表单；Esc 取消 | 新增、编辑、排序真实变化，非法修改不落入任务 |
| 证据与确认 | 详情→关联当前正文具体版本/产物→勾选核对→学生确认 | 缺证据/旧证据/依赖未确认阻止；保留旧证据；返工原因与确认记录 | 证据/确认可追溯，进度随本人确认变化 |
| 规划路径 | 顶部「个人规划」→暂不规划/填写→保存 | 没有规划说明仅依据已知截止，不推断效率；取消保留原设置 | 两种路径可继续，规划不自动移动任务 |
| 调整候选 | 查看调整→触发原因/差异→采纳或保留原计划 | 校验当前版本、环/日期/硬截止；无可行方案解释；取消不变更；撤销生成新版本 | 未采纳不写任务，旧候选不能覆盖，历史不倒退 |
| 跨页与历史 | 任务 query 定位、证据→写作/资料、反馈来源→反馈 | 缺失任务明确提示；返回保留项目内状态 | 反馈采纳创建任务可在计划找到，项目之间隔离 |

复用 StageRoute、TpField、TpButton、TpStatus、EvidenceChip 及现有时间轴布局。墨为正式任务，铅笔为候选，印章只用于学生确认。字号和间距按 DESIGN-SPEC；桌面主次栏，窄屏纵向；不新增独立主题。

执行检查：计划规则单元回归（循环/截止/陈旧/撤销/证据）、相关浏览器流程、统一类型与构建检查。正式产品 AC 仍须后续集成验收。

## 本轮执行

已实现：

- `ScreenPlan.vue` 保留原有主次栏、阶段航线和时间轴；加入新增/原地编辑、显示排序、前后置依赖、任务状态、正文与资料版本关联、学生确认、返工、任务及计划历史、个人规划两条路径。
- `planState.ts` 使用统一项目状态，空白项目从计划 v1 开始且不复制样例任务；从项目首次设置初始化个人规划。反馈仅在学生采纳后通过 `addFeedbackTask(state, input, hardDeadline)` 创建任务，来源去重；以项目硬截止计算合法初始日期，并通过完整计划校验后才写入。正文/资料更新显示旧证据，替换、解除或恢复关联保存旧版本并回到待核验。
- 调整候选保存基础版本和实际前后日期；程序检查依赖环、无效/冲突日期、硬截止、基础日期和版本，拒绝无可行结果。生成候选不改任务，采纳与撤销都保留历史，撤销产生新版本。重复确认不重复写入。
- 计划阶段读取项目绑定的流程快照，证据链接携带实际版本；计划调整仍为明确标注的自制样例，不向任意新任务套用固定建议。两周时间轴为局部窗口，完整起止时间可在任务详情和历史查看。
- `validatePlanState` 验证备份模块结构、历史快照、关联类型和依赖约束。正式后端和真实模型未接入；保存/刷新边界由统一预览外壳说明。
