# 统一自定义控件：配置与公共页面迁移

日期：2026-11-14。用户要求不再使用浏览器默认基础控件，明确指出 Select 外观不符合预期。本轮沿用原12个业务页面与组件展台，不新增页面；只替换控件的交互外壳，保留原业务规则和状态。

## 迁移范围与功能约束

| 原入口 / 功能 | 自定义控件与保留内容 | 验收 |
|---|---|---|
| 配置库筛选、API协议和模型/提示词绑定，F15—F18 | `TpSelect`显示全部原选项；停用条目仍按原规则标注，提示词的数值版本与选择联动不变 | 配置筛选、编辑、提示词绑定、历史查看不丢值；不能静默选择最新版本 |
| 流程绑定、阶段前置、阶段日期，F03/F19 | 流程历史和当前阶段选择复用`TpSelect`，阶段开始与截止复用`TpDatePicker` | 历史版、已停用前置显示及现有依赖验证保留；ISO日期保存不变 |
| 项目当前阶段与截止，F02 | 自定义阶段选择保留“当前流程不存在”禁用选项；自定义日期输入保持原日期校验 | 未迁移的阶段不被自动替换，创建/编辑行为不改变 |
| 账户静默时间，F01/F08 | `TpDatePicker type="time"`，保留`HH:mm`存储 | 原静默规则仍按相同时间值执行 |
| 收件箱/页内提醒延后，F08 | 自定义日期时间面板与手输输入；原未来日期验证、通知历史不变 | 错误仍保留当前输入；提交同一ISO日期时间 |
| 后台任务筛选，F19 | `TpSelect`保留全部状态及映射标签 | 切换筛选不改变任何任务执行状态 |
| 今日下一阶段，F03 | 自定义选择保留默认下一阶段与依赖允许项 | 没有新增自动完成动作，完成仍走原确认链 |
| 组件展台 | 原有表单示例直接展示统一 Select 和日历；不另加新页面 | 四主题共用语义令牌，错误、禁用、键盘与选中态一致 |

所有控件保留原`id`、可访问名称、帮助/错误关联和表单属性；选择项的字符串/数值类型保持。原生语义输入仍可用作自定义控件内部的可访问输入，不再露出浏览器默认选择弹层。普通文本、搜索、复选等由统一样式处理，不改正文或对象版本。

## 同轮追加：功能动效对应

用户随后明确要求每个具体功能有规范对应动效，不允许新增或展开内容直接跳出。新增动效不改变业务状态或操作顺序。

| 功能变化 | 规范动效 | 不变约束 |
|---|---|---|
| 项目/配置/阶段/字典表单打开、取消、保存关闭 | `tp-swap`，显式单根与稳定对象key | 不重置正在编辑的表单，不改变提交/校验 |
| 项目新增、归档、恢复与筛选 | `tp-list`，项目id作为key | 保留原项目、当前绑定与数据隔离 |
| 通知筛选、忽略、延后、放回，历史记录新增 | `tp-list`；补充/延后表单`tp-swap` | 不重复接收通知，不代替用户作决定 |
| 配置列表新增/筛选、详情/历史切换、阶段/分类新增 | `tp-list`、`tp-swap` | key使用配置id/阶段id/分类id或实际历史版本，不用列表位置 |
| 后台任务筛选、状态变更和详情切换 | 列表`tp-list`，状态/详情`tp-swap` | 已运行任务不重新发起，不让状态动画伪造成功 |
| 保存、导出、备份准备/错误/恢复提示 | 局部`tp-swap`；恢复准备区域`tp-swap` | 不在自动保存时使整页闪动，不隐藏持续错误 |
| 今日待决定项、任务证据和阶段确认后内容变化 | 对象列表`tp-list`、局部状态`tp-swap` | 正文、任务确认和进度计算口径不变 |
| 页内提醒切换与延后表单 | 通知id驱动`tp-swap`，表单独立展开过渡 | 仍只在今日/计划展示L3，不增加模态提醒 |
| 原生details的说明/历史展开 | 全局统一折叠规则由主任务处理 | 保留details/summary键盘语义 |

动效全部复用主题时长/曲线令牌；减弱动效由全局规则统一降为不超过120ms的淡入淡出，禁用位移。对话框及自定义选择器复用组件自身动效，不叠加二次浮起。

## 实施与验证记录

实施文件：`ScreenSettings`、`ScreenProjects`、`ScreenAccount`、`ScreenInbox`、`ScreenJobs`、`ScreenToday`、`ProjectNotice`及`PageComponents`。共享组件由各组件任务负责；本任务只迁移页面绑定。

本任务实际迁移18处Select、8处日期/时间/日期时间输入，3处原无样式复选框补统一`tp-checkbox`。所有旧`tp-input`从自定义组件外层移除，避免重复边框；配置页筛选宽度规则改为组件外层`settings-filter`，保留窄屏布局。选项标签、字符串/数值值、禁用旧阶段、提示词改选联动和版本历史未删减。

实际执行：8个所属Vue文件`vp fmt`成功（503ms），配置筛选布局调整后该文件再次格式化成功（509ms）；8文件定向`vp lint ... --format unix`退出0、无输出。静态扫描本范围原生Select和原生日历/时间输入均为0。检查时共享组件尚未落盘，未运行类型检查、构建或E2E；这些由主任务在共享组件完成后统一执行，不能把静态替换视为已通过可操作验收。


### 动效追加实施记录

本轮在原有8个文件之外接管既有`ScreenExport.vue`，未新增页面。9文件现有47处`Transition`（包含组件展示原有示例）与16处`TransitionGroup`：项目表单/归档筛选、配置分类与编辑/版本差异/阶段/字典、通知历史与延后/补充表单、任务状态与详情/尝试历史、阶段确认/待办/决定项、账户保存状态、导出/恢复反馈均采用统一动效。全部列表使用业务实体标识或历史尝试序号作为key，并绑定`listMotionHooks`冻结退出几何尺寸；多列项目卡片不会拉满整行。原生details的展开由全局样式统一负责。

配置编辑焦点在表单进入后转移；用户已移至其他可聚焦目标时不抢回焦点。新增版本差异/报告列表容器保留原有纵向间距。

静态验证：9文件`vp fmt`成功（438ms），`vp lint ... --format unix`退出0；9文件经Vue `parse`与`compileTemplate`检查均无模板错误。最后两项焦点/间距修正另行格式化及静态检查。未在本分支运行构建或浏览器验收，完整集成由主任务执行；不将静态检查写成已通过视觉验证。


### 集成验收修正：同一区域的状态替换

完整集成验收发现，任务从运行中取消时，`.settings-run-result`旧状态离场与新状态入场曾同时占位。本轮将8个归属文件内23处以key替换内容的`tp-swap`设为`mode="out-in"`，覆盖配置执行结果、保存/导出/恢复状态、错误提示、阶段表单和任务状态，确保旧内容退出后再呈现新内容，避免面板重叠与重复可访问节点。只出现/消失且无替代内容的条件区域保留原模式；既有表单`after-enter`焦点保护不变。定向8文件格式化、Lint与Vue模板静态编译通过，后续浏览器复验由主任务执行。
