## 协议与所有权

- 服务端正式模式 `TP_AUTH_MODE=workspace` 使用配置 `TP_WORKSPACE_ORIGIN`、`TP_WORKSPACE_ACCESS_KEY`、`TP_WORKSPACE_SESSION_SECONDS`。本机工作区默认使用回环同源地址，允许的 Host 和写入 Origin 按配置匹配；正式普通接口只使用服务器验证的 HttpOnly、SameSite=Strict 会话 Cookie。随机会话值只进入 Cookie，数据库保存摘要、到期时间与撤销状态。业务服务继续各自控制事务，鉴权独立读取。开发模式原有 Bearer 路径照常验证，正式模式不安装带凭据的开发代理。
- 接口 `POST /api/v1/workspace/session` 输入 `{access_key}`，`GET /api/v1/workspace/session` 查询，`DELETE /api/v1/workspace/session` 同源撤销。查询及成功建立返回 `{workspace_id, expires_at, profile}`。`PATCH /api/v1/workspace/profile` 输入 `{expected_version, display_name, notifications_enabled, quiet_start, quiet_end, show_deferred}`，返回带 `version` 的资料与偏好。失效会话读取统一返回 401，写入来源不匹配返回 403，资料旧版本返回 409。API 会话与业务响应禁缓存。退出失败可重试，成功前不声称服务端已撤销。
- 空白创建复用现有项目正文事务，通过 `POST /api/v1/projects/{project_id}/documents/blank` 建立初始版本，历史来源为 `blank`。旧正文导入及版本数据由迁移保留。
- 后端代理独占 `modules/workspace/`、对应单测与真实 PostgreSQL测试。写作前端代理独占写作页面、正式稿/历史组件及正文、草稿与命令状态需调整的文件。工作区前端独占新增 `apps/web/src/workspace/` 中的壳、解锁、项目与账户。主协调者整合配置、中央鉴权、迁移、API/前端入口、构建、生成契约和证据，串行处理跨所有权边界。
- 过渡映射：会话加载/失效、项目切换、表单打开、保存错误与历史面板复用设计规范状态和过渡，真实切换即时生效；键盘焦点跟随视图，退出视图停止交互，减弱动效不超过 120ms 且无位移。按四主题、390px、键盘与减弱模式实际操作核对。

- 后端 Windows 与 Linux：统一工程门槛的锁、Ruff、mypy、242 项快测、真实 OpenAPI 和单 head `20261117_0005` 通过。在独立 PostgreSQL/Redis/Linux worker 执行集成全集，首轮 32 项通过，工作区重启测试 1 项失败。该测试手动设置的 Cookie 缺正式路径，重新解锁后客户端同时携带两条同名 Cookie。改为与服务端相同的 Cookie 作用域，在真实 PostgreSQL 上复跑工作区集成，3 项通过。新增数据库从空库执行 `alembic upgrade head`，`alembic check` 无差异。
