# SG-21A 业务任务基础

本轮对应 [施工单](../../engineering/construction-orders.md#sg-21a-开工记录) 的 A 里程碑，覆盖 AC-010/015 的任务基础、F06 与 F19 的共享运行视图。基线为 `fe189c91981ade9de02114ff22780af20e8f3478`。正式个人工作区已可创建空稿、保存及查询不可变版本，诊断任务已具备 outbox、取消、续租、超时及失租恢复。

## 功能与状态

| 需求 | 入口及输入 | 结果与恢复 | 验收 |
|---|---|---|---|
| F06、AC-010：固定任务 | 写作页提交所在项目、已保存文档 UUID 和版本，发起正文结构检查 | 服务端验证归属、存在和输入结构，保存带 schema 版本的输入、配置和资源范围。拒绝未登记的类型、客户端指定的执行代码和跨项目输入 | 真实队列下保存新版本后仍读取原版本；拒绝跨项目、未知类型和畸形输入，同键异参冲突 |
| F06、AC-010：执行与结果 | worker 通过可信类型表从同一 Job 领取固定输入 | 领取记录尝试；处理按版本读稿，输出正式稿结构统计。结果按类型验证，与成功状态和产物一起提交。租约过期可重新领取，失效 token、取消或超时后的提交无效 | 真实 PostgreSQL/Redis/Linux worker；重复消息、坏 schema、取消迟到、重启/失租和事务回滚 |
| F19：项目任务中心与托盘 | 正式工作区侧栏和全局托盘进入当前项目，再进指定任务详情 | 页面与托盘共用任务源，呈现空态、加载、运行、成功、失败、取消和请求不明。详情可定位项目与来源版本；刷新恢复、切项目隔离。工作区诊断留在工程环境 | 真浏览器操作路由/刷新/直接访问、失败恢复、托盘数量和列表状态一致 |
| F19、AC-010：取消与重试 | 待处理任务可取消；失败或取消后可按原固定输入重试 | 取消以服务端状态为准；重试使用幂等请求创建新任务并关联来源，历史及产物保留；请求结果不明时重查并复用原键 | 双请求、迟到响应、终态不回退；断网和刷新后可核对实际状态 |

结构检查读取不可变版本中的真实数据。任务会保存带版本的结构统计，详情可核对来源。任务执行无权修改正文、计划、导师反馈或任何采纳决定。失败重试沿用原输入；需要查看更新后的版本时发起新检查。正式工作区只展示真实项目任务，展台沿用现有诊断体验。

任务入队及取消由原事务和 outbox 承担。新增尝试与租约领取、终态与产物分别在同一事务提交，写入继续受 token 和执行期限条件约束。迁移保留原诊断任务和原幂等哈希，已有历史计数继续保存。

## 交互与验证计划

| 触发 | 状态变化与视觉行为 | 减弱模式 |
|---|---|---|
| 打开托盘或任务详情 | 共用任务状态；复用浮层进出过渡，退出期间停止交互，关闭回焦 | 使用共享短淡入淡出 |
| 提交、重试、取消、轮询 | 真实任务行按稳定 ID 更新，活动计数来自服务端；加载、网络失败和终态通过既有状态组件呈现 | 状态内容完整，移除列表位移 |
| 切项目、刷新或直接打开详情 | 作用域变化立即隔离旧任务；以服务端结果恢复任务和详情 | 路由与就绪态采用既有减弱模式 |

后端执行 `uv sync --locked`、`uv run --locked python scripts/check.py` 及 Linux `--integration`。前端执行 `vp run check`、`vp test run`、默认与 workspace 构建、默认/Mock 浏览器回归；另用独立真实工作区和自制文稿实际启动/查看任务并核对四主题、390px、键盘和减弱动效。仓库、对话证据、展示同步及 diff 另行校验。

多步骤检查点、部分节点恢复与首个真实多步骤运行由 SG-21B 验收。此轮检查为单步骤；结果要么整次提交，要么可安全重试。各正式解析、模型、检索、反馈、计划、评审、导出和配置试跑入口归对应施工单。整单及产品 AC 继续待终验。

## 纠错与交付

- 旧 0002 升级测试最初调用新版 ORM 填充旧表，因尚无 `input_snapshot` 列失败。改用历史表结构准备项目、任务与 outbox，再完成升级；该项定向及全量复验通过。
- 列表总数与分页记录、任务状态与执行产物原先分开查询。并发提交可产生跨快照结果。分别合为一次查询，用真实 PostgreSQL 并发事务复验。
- 正式 worker 浏览器复跑曾在路由完成前记录写作页地址，第二窗口因此打开写作页。测试改为明确等到目标任务路由再读取链接，复验通过。HTTP 拦截场景首次缺启动所需的联调配置，补齐测试专用进程配置后复跑两项通过。
- Linux 首次运行 mypy 遇到内部缓存错误。Linux 改用独立缓存目录，锁定的 Windows/Linux 两侧检查均通过。
- 实现提交为 `e54329ea208ff600973058bfc895e977f60ebd59`。协调会话及三次子代理运行由本机原件导入，[开发档案](../chat-history.json)保留原件位置、可见交流和执行。源记录加密的派发文本保留已核实位置。
