# 正式页面设计稿对齐 W-A

2026-11-18，Claude Code 协调会话（Opus 5.5）。基线 `baabeaa`，认领 `4d0a664`。用户原话：“完善现有代码，你调用多个智能体子代理，实现所有缺少的功能”“你把其余的功能都跟设计稿对齐呀，你不要停下来不动”。论文编辑改用 MuffinOffice，纸面编辑由用户在 muffin-office-poc 实现后交付；写作页与 `document-import/*` 不在本轮。

## 分工与真实过程

- 三个只读子代理分别盘点外壳/项目/账户/任务中心、资料/计划/反馈、配置台与缺失页面，按“纯前端对齐 / 已有接口未接 / 需新后端”三类列差距。本轮只做前两类，第三类转 W-B 或后续，不放占位入口。
- 六个实现子代理各在独立 git worktree、独立正式实例（本机 docker PostgreSQL 18 + Redis 7.4，API/worker/dispatcher 同源服务各自 `dist-workspace`）施工并截图自审：外壳与指令面板、项目/首次设置/账户/任务中心、资料、计划、反馈、配置台。AGENTS 指定的 gpt 子代理模型在本工具不可用，实际使用 Claude Opus 5.5（配置台为 Sonnet 5.5）。
- 协调者串行合并：解决 `taskFeedbackScenario.ts` 冲突；外壳改挂 `WorkspaceSettings`（流程+四库+运行记录分页），给项目页、任务中心传入服务；首次设置向导改用资料页新的共享来源绑定状态（两路并行改动的接口不一致，联编 `vue-tsc` 报错后修正）；证据标签共享样式改为最小高度；反馈页任务链接带 `?task=` 定位。
- 收尾子代理：计划/反馈页加入外壳 KeepAlive 并在 `onActivated` 静默重读（发现正文更新后任务版本不变导致详情缓存误判，新增 `detailCurrent` 校验）；项目页响应 `?settings=`/`?create=1`；资料页支持 `?material=`，指令面板任务/资料结果深链到对象。
