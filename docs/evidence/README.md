# AI 开发证据与验证记录

目的：满足真实演进与可复现要求。**模板、摘要、官方快照和代码存在都不等于三条完整开发 Prompt 链已达标。**

## 文件组织

- `sessions/`：每次真实开发的脱敏索引与事实记录，关联需求、验收和实际提交。
- [chat-history.json](chat-history.json)：经脱敏的逐轮开发对话、智能体配置与执行、开发线路及已核对的提交。原件引用在 `source`，核心链范围和缺口在 `prompt_chains`。
- `templates/`：任务、会话和核心链模板，不计为已完成证据。
- `private/`：本地原始对话导出、截图或录屏，已被 Git 忽略；评审前另做脱敏、可访问副本。
- `work/`：仓库根的本地运行日志/临时资料，Git 忽略。关键非敏感证据应摘要进会话记录并关联受控原件。

新增需求、用户纠正、智能体执行、验证与提交按 [聊天证据 Skill](../../.agents/skills/thesispilot-chat-evidence/SKILL.md) 补录。子代理按分工整理，协调者统一更新 JSON。原件保存在本机，明确要求排除的内容由本机排除标识在后续导入时继续过滤。

本机首轮导入保留可确认属于项目的历史。混合会话取项目内的轮次。两个子代理的原始日志缺失，现有回复和执行资料来自可见历史投影，派发事实可在父聊天定位。子代理派发正文在源记录中加密，保留可核对的时间、角色、任务说明和执行结果，逐字正文标为待补。外部设计智能体关联现有任务说明，配置和执行留待原件补录。其他工具不支持导出时，可用截图或录屏保存前后文。

运行 `python -X utf8 scripts/validate_chat_history.py` 检查结构、引用、提交及常见敏感格式。本机可加 `--verify-local-sources` 核对原件哈希和排除标识。完整性及脱敏仍需人工复核。

## 每轮最小证据

1. 会话标识、日期、工具/模型（只写实际可确认信息）、需求/AC 编号与基础版本。
2. 原始输入和输出的可定位文件、时间段或消息位置；原件 SHA-256；明确是否完整、是否脱敏。
3. 人类如何选择建议、限制范围、指出错误；没有发生的问题不得补造。
4. 实际命令、退出码、输出摘要、失败和复测、人工检查范围。
5. 修改文件与实际 Git 提交；当前提交号可通过 `git log -- <记录路径>` 查询，避免自引用哈希。
6. 未完成内容、风险、下一步。取消/跳过/未执行和失败分别记录。

## 三条核心链

| 链 | 对应能力 | 当前状态 |
|---|---|---|
| CHAIN-001 | 证据驱动进度与依赖重排，AC-003/004/009 | 已定位需求对话，缺实现和用户引导修复的完整链 |
| CHAIN-002 | 受控修订与保护校验，AC-005/006 | 已定位写作原型交互，缺保护规则纠错与复测的完整链 |
| CHAIN-003 | 采纳、冲突与恢复，AC-007/008/010/012 | 有预览和部分工程验证索引，缺论文候选采纳与恢复对话 |

每条链沿用真实开发过程，在 [核心链模板](templates/prompt-chain.md) 中关联原始证据；修复记录应源于实际出现的问题。完整链须人工逐条审阅，自动校验器不能证明对话完整或真实性。

## 隐私与评审副本

原始资料保留在受控位置，脱敏副本单独保存。说明删除了哪些类别，不改写含义或拼接出从未发生的对话。密钥绝不进入 Git；真实论文和导师个人信息必须获授权且最小化使用。

公开快照只用于核验规则。模型实时输出、固定响应测试、录像回放、人工生成样例分别标注。原始日志缺失时直说缺失，不事后编写所谓原始输出。
